# План разработки

Рабочий журнал задач проекта «виртуальный стол для D&D». Файл можно и нужно
править: отмечайте сделанное, добавляйте своё, выбрасывайте ненужное.

- `[ ]` — не начато, `[~]` — в работе, `[x]` — готово.
- Приоритеты: **P0** — без этого рискованно играть по сети; **P1** — заметно
  улучшает стол; **P2** — полировка и вкусности.
- Оценка: **S** — один вечер, **M** — два-три вечера, **L** — больше недели
  вечеров.
- Правила ведения — в `AGENTS.md`. Пункт считается готовым только вместе с
  тестами (`ctest`), ручной проверкой «хост + клиент» со скриншотами окна,
  обновлением `AGENTS.md` и коммитом на русском.

## Состояние на 21.11.2026

Готова играбельная основа:

- Хост/DM и TCP-клиенты, меню Host/Join/Map, пароль (challenge-response),
  лобби с составом, `/kick`, лимиты пиров и команд, `TCP_NODELAY`. После
  правки мира пиру уходит только его дельта вида — токены, вошедшие в туман
  или ушедшие из него, и изменившиеся клетки тумана; полный `ViewUpdated`
  остаётся для входа и смены сцены.
- Туман войны на каждого игрока: обзор только от его персонажей, чужие
  токены скрыты, исследованные клетки помнятся; у DM — `/reveal`. До выбора
  персонажа игрок видит общий обзор партии.
- Бой: автобросок инициативы с бонусом из листа, раунды, ходы, лимит движения
  по скорости (диагонали по правилу 5–10–5), сброс запаса в начале хода.
- Токены: типы, владельцы, claim/release одним персонажем, `/owner`, лист
  персонажа (КД, скорость, бонусы, урон, заметки, временные HP, кость хитов,
  модификатор Телосложения), состояния с длительностью, цвета,
  переименование, max HP, опыт и уровень, портреты.
- Уровень по правилам 2024: прирост максимума и текущих HP по среднему кости
  хитов и модификатору Телосложения, бонус мастерства по рубежам (5/9/13/17
  поднимает бонусы атаки и спасброска в листе), напоминания о повышении
  характеристик (4/8/12/16) и эпическом даре (19).
- Кубы: `/roll`, `adv`/`dis`, атака (Shift — преимущество, Ctrl — помеха),
  спасбросок, инициатива, урон; подписи с именем токена.
- Атака автоматизирована: `A` по цели под курсором сравнивает d20 + бонус с
  КД, крит удваивает кости урона, промах и 1 не наносят урона; сервер сам
  применяет урон из листа цели (временные HP, «без сознания», концентрация).
- Правила: урон и лечение, временные HP, спасброски от смерти, концентрация,
  отдых по костям хитов (короткий тратит, длинный возвращает), шаблоны
  областей (круг/конус/линия) со спасбросками.
- Метры (1 клетка = 1,5 м), дальность движения с учётом тумана, линейка по
  `Alt`+ЛКМ, пинг `Alt`+ПКМ, проверка пути вне боя.
- Бестиарий из 9 шаблонов, спавн одного монстра и группы 3–5 (`Shift`+цифра)
  в свободные клетки вокруг курсора.
- Кампания из сцен: библиотека `*.dndcamp` рядом с `.exe` с выбором в меню,
  панель по `Tab`, `/scene`, копирование/удаление сцен, заметки и
  переименование, автосейв, смена сцены с полной пересинхронизацией через
  `ViewUpdated`.
- Редактор карт: стены, размер, стартовые токены, `scene.dndscene`.
- Стол: прокрутка лога, `session.log`, справка `F1`, журнал `F3` с поиском и
  прошлыми сессиями, масштаб интерфейса, мышь в списках, подложка карты,
  круглые портреты, `Ctrl+Z` для DM, подтверждение удаления двойным `Del`.
- Разбор чат-команд в ядре (`ParseChatCommand`) с тестами; в `net_tests`
  есть сценарий двух клиентов за столом.
- Логика стола вне SDL: камера и зум, меню, навигация по сценам и файлам,
  отложенный автосейв, прокрутка лога, подтверждение удаления и строка
  чата живут в `src/core` и покрыты `core_tests`; `App` осталась клеем
  между SDL и командами.

Версии форматов: `kSaveVersion = 26`, `kProtocolVersion = 36`,
`kCampaignVersion = 13`. Тесты — `core_tests` и `net_tests`, оба зелёные.
Свои файлы собираются с `-Wall -Wextra -Wpedantic` без предупреждений;
`clang-tidy` по флагу `-t` замечаний не находит. Интерфейс проверен на живом
окне (хост + клиент): отдельный туман, `M`, отказ «Клетка не разведана»,
`/xp`, `Ctrl+Z`, `/reveal`, `/unreveal`, журнал `F3` с поиском и `КХ` в
карточке токена.

## Аудит: что мешает и чего не хватает

Проверено чтением кода и на живом окне (хост + клиент, 21.11.2026).
Закрыто с прошлого аудита: открытый пароль, невнятный отказ при чужой
версии, отсутствие лимитов, `TCP_NODELAY`, партийный туман, состояния без
длительности/отдыха/опыта/концентрации, подложка и портреты, путь вне боя,
сброс тумана при `Reset` (пункт 4), регистр имён (пункт 9), открытый трафик
(пункт 2), повышение уровня (пункт 5), атака с уроном (пункт 6), точечное
закрытие открытых областей (пункт 7), инкрементальная синхронизация вида
(пункт 8), чтение и поиск журнала (пункт 10), отдых по костям хитов
(пункт 11).

1. **Сеть только под Windows**: `#error` в `src/net/tcp_socket.cpp`; сборка
   и тесты на Linux/macOS не пойдут.
2. **Трафик открыт** — готово: после рукопожатия все кадры шифруются
   (X25519 + ChaCha20 + HMAC-SHA256, ключи через HKDF-SHA256). Открытыми
   остаются только `Challenge`, `Hello` и отказ до проверки пароля.
3. **Логика `App` без тестов** — готово: камера (`core/camera`), переход
   по вкладкам и полям меню с разбором адреса (`core/menu_model`),
   навигация по сценам и файлам (`core/navigation`), отложенный автосейв
   (`core/autosave`), прокрутка лога (`core/log_scroll`), подтверждение
   удаления (`core/delete_confirm`), строка чата и UTF-8-ввод
   (`core/chat_input`, `core/utf8`) вынесены в ядро и покрыты
   `core_tests`. В `App` остались SDL, отрисовка и связывание команд;
   панели по-прежнему проверяются на живом окне.
4. **Туман обнуляется при `Reset`** — готово: туман хранится в сцене
   (`GameSnapshot::fog`, только исследованные клетки), сервер восстанавливает
   его в `GameServer::Reset`, поэтому `Ctrl+Z`, `F9` и смена сцены больше не
   заставляют игроков исследовать карту заново. Карта другой формы начинает
   с чистого тумана, клиенту уходит только его срез.
5. **Повышение уровня ничего не даёт** — готово: уровень по-прежнему
   вычисляется по опыту, но повышение меняет лист по правилам 2024.
   За каждый новый уровень максимум HP растёт на среднее кости хитов
   (d6 4, d8 5, d10 6, d12 7) плюс модификатор Телосложения, но не меньше 1;
   текущие HP растут на столько же, если персонаж не лежит на нуле. На
   рубежах 5/9/13/17 бонус мастерства (+2…+6 по уровню) поднимает итоговые
   бонусы атаки и спасброска в листе, на 4/8/12/16 лог напоминает о
   повышении характеристик, на 19 — об эпическом даре. Кость хитов и
   модификатор Телосложения — поля листа (`L`); КД от уровня в 2024 не
   зависит, поэтому остаётся ручным.
6. **Атака не автоматизирована** — готово: `A` бьёт токен под курсором
   выбранным токеном. Сервер бросает d20 + бонус атаки против КД цели,
   natural 20 — критическое попадание с удвоенными костями урона, natural 1 —
   промах. При попадании урон из листа применяется сразу: временные HP,
   «без сознания» и проверка концентрации те же, что у `/damage`. Shift+A —
   преимущество, Ctrl+A — помеха. Цель должна быть видна атакующему.
   Чистая проверка броска и крит-урона — `core/attack`, тест — `TestAttack`;
   версия протокола — 31.
7. **`/reveal off` стирает все открытые клетки**, точечно закрыть участок
   нельзя — готово: `/unreveal` закрывает круг 4 клетки под курсором, не
   трогая остальные открытия, `/reveal off` по-прежнему снимает все.
   `GameState` хранит `revealed_` отсортированным по (y, x): `IsRevealed` —
   двоичный поиск, `RevealArea`/`HideArea` сливают и вычитают области за
   один проход вместо линейного поиска на каждую клетку. Версия протокола —
   32, тесты — `TestRevealedAreas`, `TestSeparateVisibility`.
8. **Полный снапшот каждому пиру на каждое изменение мира** (`ViewUpdated`) —
   готово: после правки мира хост считает дельту вида на игрока и шлёт только
   её. Токены, вошедшие в туман, уходят `TokenAdded`, ушедшие из него —
   `TokenRemoved`, а изменившиеся клетки тумана (видимость и разведанность)
   едут в `FogChanged`. Слепок «уже отправлено» держит `GameServer`
   (`TakeViewDelta` обновляет его сам, `MarkViewSent` начинает заново после
   полного вида), поэтому полный снапшот ходит лишь при входе и смене мира.
   Трафик правки больше не зависит от размера карты. Версия протокола — 35,
   тесты — `TestIncrementalView`, `TestFogChangedRoundtrip`.
9. **Кик обходится сменой регистра** — готово: имена игроков сравниваются
   без учёта регистра (`PlayerNameKey`/`SamePlayerName` в
   `src/core/player_name`), поэтому кик по `player` закрывает вход и как
   `Player`, дубликаты имён ловятся в любом регистре, а персонаж с владельцем
   `player` отдаётся игроку `Player`. Тем же ключом живёт туман игроков.
10. **Лог в памяти — 200 строк**, интерфейс не читал `session.log` — готово:
    `F3` открывает модальный журнал (`core/log_history`,
    `DrawLogHistoryPanel`) и читает файл с диска: последние
    `kMaxHistoryLines` (2000) строк, хвост не больше 512 КиБ, чтобы старый
    журнал не грузился целиком. Заголовки `=== сессия ... ===` разделяют
    прошлые сессии, поиск по автору и тексту идёт без учёта регистра тем же
    ключом, что и имена (`PlayerNameKey`); Enter не нужен — фильтр
    пересчитывается на каждый символ. `↑`/`↓`, `PgUp`/`PgDn`, колесо и
    `End` листают найденное. Тест — `TestSessionLogHistory`.
11. **Отдых и уровни не связаны с правилами** — готово: отдых идёт по
    костям хитов (2024). Запас костей равен уровню (`HitDiceMaximum`), тратится
    коротким отдыхом `/rest`: каждая кость лечит `HitDieHeal(d{h}, Телосложение)`
    (не меньше 0), пока не восстановлен максимум HP или не кончились кости.
    Длинный отдых `/longrest` возвращает HP, все кости и снимает состояния.
    Потраченные кости хранит `Token::hit_dice_spent`, их видно в карточке
    токена (`КХ: осталось/всего`), отдых пишет подробную строку в лог.
    Версии сохранения и протокола — 26 и 36, тесты — `TestShortRestHitDice`,
    `TestDamageHealRest`, `TestLevels`.
12. **Автосейв пишет всю кампанию синхронно** в кадре: с ростом числа сцен
    растут и файл, и пауза.

## Этап 1. Сеть для игры по интернету (P0, M)

### 1.5 Шифрование всего трафика (пункт 2 аудита) — готово

- [x] Свой слой вместо TLS: TLS в `SDL3_net` нет, а сторонняя криптобиблиотека
      ради одного обмена ключами не нужна. Примитивы в `src/core`: `x25519`
      (RFC 7748), `chacha20` (RFC 8439), `session_crypto` (HKDF-SHA256,
      отпечатки и шифрование кадров). Случайные байты — `src/core/random`
      через системный `rand_s`: `std::random_device` на MinGW предсказуем.
- [x] Рукопожатие: `Challenge` несёт случайный nonce и эфемерный ключ хоста,
      `Hello` — ключ клиента и отпечаток HMAC-SHA256(пароль, транскрипт:
      nonce, оба ключа, имя), `SessionReady` — ответный отпечаток хоста.
      Транскрипт в отпечатке не даёт подменить ключи посреди соединения,
      а обратный отпечаток доказывает клиенту, что хост знает пароль.
- [x] Из общего секрета X25519 и HKDF выводятся ключи на каждое направление;
      дальше кадры идут как `[маркер][номер u64][шифртекст][MAC 32]`
      (ChaCha20 + HMAC-SHA256, encrypt-then-MAC). Номер кадра входит в MAC:
      повтор, перестановка и обрезка рвут соединение, как и открытый кадр
      после рукопожатия.
- [x] Открытыми остаются только `Challenge`, `Hello` и отказ, выданный до
      проверки пароля: в них нет ни мира, ни переписки.

## Этап 3. Бой и правила (P1, M–L) — готово

- [x] Автобросок инициативы в начале боя: сервер кидает d20 + бонус из листа
      за каждый токен, пишет результат в `initiative` и строку в лог. В листе
      появилось поле «Бонус инициативы».
- [x] Состояния с длительностью: `Condition{имя, секунды, КС}`; состояния из
      панели `K` ставятся на 1 минуту (`Shift+1–8` — до снятия), остаток виден
      в панели и на токене. В бою время идёт по 6 секунд за ход и тикает в
      начале хода своего токена; вне боя DM двигает время командой `/time N`
      (по умолчанию минуты, `s`/`m`/`h`), отдых тоже двигает время. В конце
      хода состояние с КС даёт спасбросок d20 + бонус спасброска; успех
      снимает состояние, итог пишется в лог.
- [x] Урон и лечение командой (`/damage N`, `/heal N` по выбранному токену):
      временные HP принимают удар первыми, при 0 HP ставится «без сознания»,
      лечение снимает его, всё пишется в лог.
- [x] Спасброски от смерти: `/deathsave` у токена с 0 HP, счётчики успехов и
      провалов в токене; 3 провала — «мёртв», 3 успеха — стабилен, 20 — 1 HP;
      удар по лежачему добавляет провал, лечение и отдых сбрасывают счётчики.
- [x] Отдых: короткий (`/rest`, 1 час и половина максимума HP) и длинный
      (`/longrest`, 8 часов, полный сброс HP, временных HP и состояний);
      объявляет только DM, итог пишется в лог. Время отдыха истекает у
      срочных состояний всех токенов.
- [x] Концентрация: при уроне сервер кидает d20 + бонус спасброска против
      10 или половины урона; провал снимает состояние, итог пишется в лог.
- [x] Применение шаблона области: `Enter` в режиме `F` готовит `/aoe 2d6 15`;
      сервер кидает урон один раз, каждому попавшему токену — спасбросок
      против сложности (успех уменьшает урон вдвое, провал — полный урон).

Порядок внутри этапа: урон → отдых → игровое время и длительность состояний →
автобросок → концентрация → область.

Приёмка: бой от начала до нуля HP у монстра целиком одним игроком и одним
DM-ом, лог читается как протокол боя.
