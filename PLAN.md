# План разработки

Рабочий журнал задач проекта «виртуальный стол для D&D». Файл можно и нужно
править: отмечайте сделанное, добавляйте своё, выбрасывайте ненужное.

- `[ ]` — не начато, `[~]` — в работе, `[x]` — готово.
- Приоритеты: **P0** — без этого рискованно играть по сети; **P1** — заметно
  улучшает стол; **P2** — полировка и вкусности.
- Оценка: **S** — один вечер, **M** — два-три вечера, **L** — больше недели
  вечеров.
- Правила ведения — в `AGENTS.md`. Пункт считается готовым только вместе с
  тестами (`ctest`), ручной проверкой «хост + клиент» со скриншотами окна,
  обновлением `AGENTS.md` и коммитом на русском.

## Состояние на 18.11.2026

Готова играбельная основа:

- Хост/DM и TCP-клиенты, меню Host/Join/Map, пароль, лобби с составом,
  `/kick`.
- Туман войны по всем персонажам партии, исследованные клетки в памяти.
- Бой: инициатива (вручную), раунды, ходы, лимит движения по скорости,
  сброс запаса в начале хода.
- Токены: типы, владельцы, claim/release одним персонажем, `/owner`,
  лист персонажа (КД, скорость, бонусы, урон, заметки, временные HP),
  состояния (8 фиксированных), цвета, переименование, max HP.
- Кубы: `/roll`, `adv`/`dis`, атака (Shift — преимущество), спасбросок,
  инициатива, урон; подписи с именем токена.
- Метры (1 клетка = 1,5 м), дальность движения, линейка по `Alt`+ЛКМ,
  шаблоны областей (круг/конус/линия) у DM.
- Бестиарий из 9 шаблонов, спавн одного монстра и группы 3–5 (`Shift`+цифра)
  в свободные клетки вокруг курсора.
- Кампания из сцен: `campaign.dndcamp`, панель по `Tab`, `/scene`,
  копирование/удаление сцен, смена сцены с полной пересинхронизацией
  клиентов через `ViewUpdated`.
- Редактор карт: стены, размер, стартовые токены, `scene.dndscene`.

Версии форматов: `kSaveVersion = 18`, `kProtocolVersion = 24`,
`kCampaignVersion = 6`. Тесты — `core_tests` и `net_tests`, оба зелёные.
Свои файлы собираются с `-Wall -Wextra -Wpedantic` без предупреждений;
`clang-tidy` по флагу `-t` замечаний не находит.

## Аудит: что мешает и чего не хватает

Найдено чтением кода, не по ощущениям:

1. **Пароль идёт открытым текстом** в `Hello` и сравнивается строкой
   (`src/net/net_server.cpp`, `src/net/protocol.cpp`). В интернете его видит
   любой на пути; повторы и вес пароля не защищены.
2. **Несовпадение версии протокола неотличимо от мусора**: версия в `Hello`
   есть, но `DecodeHello` отвергает такой пакет, и клиент видит
   «некорректное приветствие» вместо «обновите игру».
3. **Нет лимитов на клиентов и очереди**: `NetServer` принимает сколько
   угодно пиров, а `TcpConnection::QueueFrame` копит исходящие байты без
   предела — один медленный клиент съест память хоста.
4. **TCP_NODELAY не включён**: мелкие события (ход, чат) ждут алгоритма
   Нейгла, отклик хуже, чем мог бы.
5. **Сеть только под Windows** (`#error` в `src/net/tcp_socket.cpp`);
   `SDL3_image` используется для подложки карты (этап 5).
6. ~~Нет флагов предупреждений и прогона `clang-tidy` вне IDE~~ — сделано на
   этапе 0.
7. **Туман только партийный** (одна `FogOfWar` в `GameServer`): нельзя дать
   одному игроку отдельную видимость или вручную раскрыть область DM-ом.
8. **Лог короткий и без управления**: 200 строк в памяти, 7 на экране,
   без прокрутки, без записи в файл.
9. **Состояния — просто строки** (`Token::conditions`), без длительности и
   источника; нет отдыха, опыта, уровней, концентрации.
10. **Инициатива вводится числом вручную**, автоброска в начале боя нет.
11. ~~Нет подложки карты и картинок токенов~~ — сделано на этапе 5: подложка
    и круглые портреты.
12. **Логика `App` не покрыта тестами**: сцены, кампания и чат-команды
    проверяются только руками.
13. **Нет справки по клавишам** (`F1`): подсказки внизу зависят от роли, но
    не от контекста, и в них не всё перечислено.
14. **Опасные действия без подтверждения**: `Del` сразу удаляет токен,
    `Del` в панели сцен — активную сцену.
15. **Вне боя путь не проверяется**: двигается только клетка назначения,
    сквозь стены и через всю карту; токены друг друга не блокируют,
    диагональ стоит один шаг без правила срезания углов. Решить, что из этого
    оставить намеренно.

## Этап 1. Сеть для игры по интернету (P0, M)

### 1.1 Понятный отказ при чужой версии — готово
- [x] Разделил «битый пакет» и «другая версия»: `DecodeHelloVersion` читает
      только тип и версию из заголовка `Hello`, при несовпадении хост
      отвечает `Reject` с текстом «версия игры не совпадает: у хоста N,
      у клиента M; обновите игру». Причина показывается в меню клиента.
- [x] Тест `TestVersionMismatchReject` в `tests/net_tests.cpp`: сырое
      подключение шлёт `Hello` с чужим номером версии и получает отказ,
      в котором названы обе версии.

Файлы: `src/net/protocol.h/.cpp`, `src/net/net_server.cpp`,
`src/app/app.cpp` (показ причины в меню).

### 1.2 Защита от медленных и шумных клиентов — готово
- [x] Предел `kMaxPeers = 8`: девятый пир получает `Reject` «на хосте нет
      свободных мест». Отказное соединение живёт ~2 с (всего не больше
      восьми таких), чтобы клиент успел прочитать причину.
- [x] Предел очереди отправки `kMaxOutgoingBytes` (1 МиБ) в `TcpConnection`:
      при переполнении соединение закрывается, хост продолжает работу.
- [x] Частота команд на пира ограничена `kMaxCommandsPerSecond` (30 в
      секунду, окно в секунду); лишние молча отбрасываются.
- [x] `TCP_NODELAY` включён для соединений через `ConfigureSocket`.

Файлы: `src/net/tcp_socket.cpp`, `src/net/net_server.h/.cpp`.
Приёмка: `net_tests` покрывает лимит пиров, переполнение очереди и всплеск
команд (`TestPeerLimit`, `TestOutgoingQueueLimit`, `TestCommandRateLimit`).

### 1.3 Пароль — вариант B готов
- [x] Выбран вариант **B (M)**: challenge-response, пароль по сети не ходит.
      Свой минимальный SHA-256/HMAC в `src/core/sha256` (FIPS 180-4, RFC 2104),
      векторы проверены в `core_tests` (`TestSha256`).
- [x] Новое сообщение `Challenge` (тип 8): хост сразу после подключения шлёт
      случайный nonce (16 байт, `RandomChallenge`).
- [x] `Hello` вместо пароля несёт отпечаток HMAC-SHA256(пароль, nonce); сервер
      сверяет его `ProofMatches` (сравнение без раннего выхода). Повтор Hello
      после входа отвергается, попытки входа ограничены общим лимитом
      сообщений пира — при переборе соединение закрывается.
- [x] Версия протокола поднята до 17: раскладка `Hello` изменилась, старые
      клиенты получают понятный отказ.
- [ ] **C (L)** — TLS через `SDL3_net`: скрывает весь трафик, не только пароль.
      Пока не делаем, вернуться, если понадобится прятать и переписку.

Файлы: `src/core/sha256.h/.cpp`, `src/core/password.h/.cpp`,
`src/net/protocol.h/.cpp`, `src/net/net_client.h/.cpp`,
`src/net/net_server.h/.cpp`.
Приёмка: `net_tests` проверяет отказ на чужой отпечаток (`TestChallengeHandshake`)
и вход с верным/неверным паролем (`TestPasswordAndRoster`).

### 1.4 Реконнект и аварии — готово
- [x] Клиент после обрыва: баннер «Связь потеряна, переподключение…»
      (`DrawConnectionBanner`) и строка в логе стола вместо тихого ожидания
      замороженного вида.
- [x] После реконнекта `Welcome` перезаливает мир, а `PruneStaleViewState`
      сбрасывает выделение и закрывает лист/состояния, если токена уже нет.
      Переподключение повторяется раз в 2 с, пока хост не ответит.
- [x] Хост при падении игрока не трогает владение: персонаж остаётся за ним,
      DM снимает владельца `/owner` (пустое имя) и может отдать другому.
      Записано в `AGENTS.md`.
- [x] Кик (`/kick ИМЯ`) = бан до перезапуска хоста: `KickByName` кладёт имя в
      `banned_names_`, снять бан командой нельзя. `TestPasswordAndRoster`
      проверяет отключение и отказ повторному входу.

Приёмка вручную: хост + два клиента, выключить сеть на клиенте на 10 секунд —
после возврата вид совпадает с хостом, бой и сцена те же.

## Этап 3. Бой и правила (P1, M–L) — готово

- [x] Автобросок инициативы в начале боя: сервер кидает d20 + бонус из листа
      за каждый токен, пишет результат в `initiative` и строку в лог. В листе
      появилось поле «Бонус инициативы».
- [x] Состояния с длительностью: `Condition{имя, раунды}`; состояния из панели
      `K` ставятся на 10 ходов, остаток виден в панели и на токене, тик идёт в
      начале хода своего токена, `0` — до ручного снятия.
- [x] Урон и лечение командой (`/damage N`, `/heal N` по выбранному токену):
      временные HP принимают удар первыми, при 0 HP ставится «без сознания»,
      лечение снимает его, всё пишется в лог.
- [x] Спасброски от смерти: `/deathsave` у токена с 0 HP, счётчики успехов и
      провалов в токене; 3 провала — «мёртв», 3 успеха — стабилен, 20 — 1 HP;
      удар по лежачему добавляет провал, лечение и отдых сбрасывают счётчики.
- [x] Отдых: короткий (`/rest`, половина максимума HP) и длинный (`/longrest`,
      полный сброс HP, временных HP и состояний); объявляет только DM, итог
      пишется в лог.
- [x] Концентрация: при уроне сервер кидает d20 + бонус спасброска против
      10 или половины урона; провал снимает состояние, итог пишется в лог.
- [x] Применение шаблона области: `Enter` в режиме `F` готовит `/aoe 2d6 15`;
      сервер кидает урон один раз, каждому попавшему токену — спасбросок
      против сложности (успех уменьшает урон вдвое, провал — полный урон).

Порядок внутри этапа: урон → отдых → длительность состояний → автобросок →
концентрация → область.

Приёмка: бой от начала до нуля HP у монстра целиком одним игроком и одним
DM-ом, лог читается как протокол боя.

карты не делаем» — чтобы через месяц не спорить с собой.
