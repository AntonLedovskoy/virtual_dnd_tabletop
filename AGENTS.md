# AGENTS.md

Virtual D&D tabletop, C++20 + SDL3. One `virtual_dnd_tabletop` binary:
authoritative host/DM or TCP client. No CI: build scripts and tests are the
source of truth. Roadmap and weak spots in `PLAN.md`; user-facing overview in
`README.md`, kept in sync with flags, keys and chat commands.

Language: code, comments, docs in Russian; identifiers and terms in English.
**Rule: this file is English only and token-tight.** No Russian prose, no
filler, no restating the code; short lines, one fact per sentence; Russian UI
text described, not copied. Local rules win where stricter than global
(language, live UI checks).

Rules: always the latest D&D edition (2024, 5e revised). Where 2014 differs,
follow 2024 — level-up, AC, conditions, rests, movement. Old rules only as a
deliberate note in `PLAN.md`. Use the cheat sheet `docs/rules/cheatsheet-ru.md`;
source of truth is `docs/rules/SRD_CC_v5.2.1.pdf` (SRD 5.2.1, CC-BY-4.0). The
SRD wins over memory and third-party sites.

## Build and tests

- Windows: `.\build.bat` (debug default). `-p debug|release|relwithdebinfo|minsize`, `-c` reconfigure, `-j N` jobs, `-t`/`--tidy` runs `clang-tidy` on our `.cpp`, any finding fails.
- `build.bat` runs `tools/build.sh` in MSYS2 UCRT64 (`C:\msys64` or `%MSYS2_ROOT%`); never run `tools/build.sh` from PowerShell.
- Binaries in `.build/<profile>/`, e.g. `.build/debug/virtual_dnd_tabletop.exe`.
- `virtual_dnd_tabletop.exe` is a GUI subsystem without a console: `SDL_Log` appends to `virtual_dnd_tabletop.log` next to `.exe` (`src/app/file_log.h`); `--help` and startup errors open a dialog. Tests stay console.
- First configure fetches SDL3, SDL3_ttf, SDL3_image via FetchContent (network, minutes); `.build/<profile>` is reused unless `-c`.
- Our targets: `-Wall -Wextra -Wpedantic`; deps use their own flags; a new warning in our code is an error.
- All tests: `ctest --test-dir .build/debug --output-on-failure`; one suite `-R core_tests` or `.build/debug/dnd_core_tests.exe`.
- Tests: plain `main()` + `Expect`, no framework or per-test filter — add `TestX()` and call it from `main()` in `tests/core_tests.cpp`/`tests/net_tests.cpp`.
- `net_tests`: temp localhost port, 3 s timeouts, no external services.
- GUI needs a display: debug via `.vscode/launch.json`, not tests.
- UI: verify on the live GUI with client-area screenshots, not `ctest`. Run host + client, walk the scenario, snapshot each changed visual behavior. SendInput/`SendKeys` in client coordinates is fine; the outcome must be a snapshot.

## Releases

- Release = annotated `vX.Y.Z` tag on a clean `master`; the tag body becomes the `latest.json` notes: `git tag -a vX.Y.Z -m "what's new"`, then `git push origin master --tags`. `package.sh` appends a fixed tail: update in place, SmartScreen prompt on first launch.
- `.\package.bat` builds release (with `-c` so the version lands in the binary) into `dist/`: `virtual_dnd_tabletop.exe`, `virtual_dnd_tabletop-X.Y.Z-win64.zip`, `latest.json`, `notes.txt`. The zip holds the exe, `assets/fonts/DejaVuSans.ttf` and `LICENSE-DejaVu.txt`. Assets (`ASSET_PATHS` in `tools/package.sh`, now the font and its license) are also copied to `dist/upload/` under flat names (`assets__fonts__DejaVuSans.ttf`) and listed in the manifest `files` — separate release files; without them auto-update brings no font. The script checks the exe carries the tag version and imports no external DLLs (`objdump`: MinGW runtime and SDL are static, the archive holds only exe and font) and hashes it into the manifest. `--allow-dev` runs the pipeline without a tag; never publish such an archive.
- Upload: `gh release create vX.Y.Z dist/virtual_dnd_tabletop.exe dist/virtual_dnd_tabletop-X.Y.Z-win64.zip dist/latest.json dist/upload/* --title "virtual_dnd_tabletop X.Y.Z" --notes-file dist/notes.txt` (`package.sh` prints the exact list); without `gh` use the web Releases form, assets included.
- Updates bring assets: `latest.json` lists them in `files` (`path`, `url`, `sha256`, `size`); `UpdateService` downloads only missing or changed ones (sha256 vs disk) into `<path>.update` next to the destination, `InstallDownloadedUpdate` applies them **before** the exe swap, and `ApplyStartupRecovery`/`RemoveStagedAssets` drops half-downloaded `*.update` under `assets/` at startup. Manifest paths are `assets/…` only (`IsSafeUpdatePath`): the exe, campaigns, log and portraits are off limits. A new asset must be harmless to the old exe: if an asset swap fails, the player stays on the previous exe and never reads extra files in `assets/`.
- The client reads the manifest via the stable link `https://github.com/AntonLedovskoy/virtual_dnd_tabletop/releases/latest/download/latest.json`.
- Bump `kProtocolVersion` → release the same day: an old client is refused on connect.
- Saves and campaigns must not break against the previous release: a new snapshot field adds a `SnapshotFormat` branch and a version, older versions stay readable.
- An update installs over the same folder: table data lives next to `.exe`.
- Update check: `src/core/update` parses `latest.json` leniently (`version`, `url`, `sha256` required); `src/app/update_service` downloads and verifies the exe in a worker thread via WinHTTP (redirect ALWAYS, 3 s/10 s, limits 64 KiB/64 MiB) into `virtual_dnd_tabletop.update.exe`. Only the exe target links the network (`winhttp`); `dnd_core` stays free of SDL and sockets.
- Menu banner "Version X available" with "Update and restart"/"Later"; version and protocol on the host tab. `DND_UPDATE_MANIFEST` sets a manifest path or URL for an offline run of the whole cycle and enables updates in a developer build. `--no-update-check` disables the check.
- Version mismatch: the host sends a text `Reject` (any version understands it) and right after a `VersionMismatch` frame (type 10) — protocol, host version and the newest version from its manifest. `AdviseUpdate` (`src/core/update`) decides who lags; the menu opens a modal version dialog with an update button only if the client must update, otherwise a releases link. `Esc`/close returns to the menu, `Enter` starts the update.
- Swap only from the menu: `CampaignSaver::Flush()`, `virtual_dnd_tabletop.exe` → `.old.exe`, `.update.exe` → `.exe`, `CreateProcess`, the old process exits. One instance per folder is held by a named mutex (`src/app/instance_lock`); `PlanStartupRecovery` heals an interrupted step before the window exists. Developer builds offer no updates.

## Architecture

- `src/core` — logic without SDL: `GameState` (rules), `GameServer` (validates commands, ownership, fog, dice), `ClientView` (state rendering reads), `LocalTransport` (in-process command/event queue), `ParseChatCommand` (`src/core/chat_command`; `/roll`, `/map`, `/scene`, ... without role or selected token), `core/damage` (types, resistances, parsing `1d8+2 fire`), `core/conditions` (palette, exhaustion, roll modifiers). Login crypto in `src/core/sha256` (SHA-256/HMAC) and `src/core/password`; session crypto in `src/core/x25519` (RFC 7748), `src/core/chacha20` (RFC 8439), `src/core/session_crypto` (HKDF, fingerprints, frame sealing); random bytes in `src/core/random` (system `rand_s`, not `std::random_device`, which is predictable on MinGW); case-insensitive names in `src/core/player_name`.
- `src/net` — TCP framing on Boost.Asio. `NetServer` is not authoritative: `App` owns `GameServer` and forwards peer commands. Asio is header-only from the system (`find_package(Boost CONFIG)`; MSYS2 `mingw-w64-ucrt-x86_64-boost`, Debian `libboost-dev`, macOS `brew install boost`); no WinSock calls, so `src/net` builds on Linux/macOS. Networking is async: `TcpConnection` and `TcpListener` each own an `io_context`, pumped by `Poll()`/`Accept()`. `QueueFrame` only enqueues, so poll a sender before its bytes leave. `Connected()` counts a connection in progress as alive. Poll host and clients in every `net_tests` wait loop, else a queued frame waits. `src/app` — SDL window/input, Host/Join menu, host/client loop; `src/render` — drawing only; entry `src/main.cpp` on SDL3 callbacks (`SDL_MAIN_USE_CALLBACKS`).
- Table logic without SDL lives in `src/core`, covered by `core_tests`: `camera` (cell under cursor, centring, zoom), `menu_model` (tabs, field order, limits, `host:port`), `ui_hint` (keys in the bottom hint), `navigation` (scene and file lists), `autosave` (deferred write), `campaign_save` (campaign write on its own thread), `overlay_save` (party write), `log_scroll`, `delete_confirm`, `chat_input`, UTF-8 editing in `utf8`. `App` only maps SDL events onto these functions and commands.
- Text only via `render/text_renderer` (`TTF_Text` + `TTF_DrawRendererText`, pooled objects, `BeginFrame()` per frame); per-frame `TTF_RenderText_Blended` textures are forbidden. `App::LoadFont` sets `TTF_SetFontLineSkip(height + 2)` after opening DejaVu: with normal hinting hinted glyphs exceed the computed line, and SDL_ttf clips Cyrillic descenders (visible in release).
- Startup: Host/Join/Map menu; `--host`, `--port`, `--connect HOST[:PORT]` start a mode, `--editor` map editor, `--menu` menu. Clients take `--name`, both sides `--password`. Host is always DM, plays locally, port 7777; names non-empty, unique, compared without case (`PlayerNameKey`, `DM` reserved in any case); `/kick NAME` removes a player and bans the folded name.
- Editor saves `scene.dndscene` next to `.exe` (snapshot format). Keys: `1`–`6` brushes, `7` road, `8` difficult terrain (cycles swamp → brush → snow → mud), `G` cell inspector, `P` character, `B` bestiary (same panel as the DM's), `M` map backdrop, `[`/`]` width, `-`/`=` height, `Tab` scenes/maps, `F2` panel, `F5` save scene, `F9` load `scene.dndscene`, `Enter` host, `Esc` menu. Map panel: `↑`/`↓`/`1`–`9` select, `Enter` open, `N` new map from the current one, `R` rename, `Del` twice delete (the last map stays). The inspector (`DrawEditorInspector`) edits the cell under the cursor: `Tab`/`↑`/`↓` field, `←`/`→` value, `Enter` applies, `Esc` closes; fields for water, current direction and strength, hazard profile, road, climbing, slippery DC, four cover sides. Left mouse on an empty cell paints while held (stroke interpolated with `core/editor_paint`); on a token it selects and drags it (`core/editor_token`), so a brush never paints over tokens. Right mouse restores the floor (and `CellProps`); with the road brush it removes only the road. A token is deleted only on the second right click within 3 s (`DeleteConfirm`). `R` renames the selected token, `V` cycles its colour, `L` opens its editable sheet (same panel as the DM's, saved into `scene_`); middle-drag pans, wheel zooms. Switching a map stores the current one in the campaign and saves it; every editor save strips party traces (`fog`, `revealed`, `encounter`, `game_time_seconds`, `last_long_rest_seconds`) so the template stays clean.
- `L` token sheet (AC, speed, swim/climb speeds, attack/save bonuses, damage, notes); `B` DM bestiary (`src/core/bestiary`, templates copied into the token on spawn; 9 templates, `Shift`+digit spawns 3–5 in free cells, `MonsterGroupCells`). Claim = one character per player, once per campaign; a player cannot release it (`R` and `/owner` are DM-only), afterwards only the DM assigns owners via `/owner`. The DM takes a free character with `C` (owner `dm`, several allowed, `C` again releases; a character held by a player changes hands only via `/owner`). Anyone opens any character sheet read-only, the DM edits it; rename (`/rename`) and colour (`V`) are DM-only. The bottom hint is contextual (`core/ui_hint`: base keys, selected token, open mode, combat, role).
- Connection loss never resets the table: banner "Connection lost, reconnecting…", `NetClient::Reconnect` every 2 s (`kReconnectDelay`). A new `Welcome` resends the world; `PruneStaleViewState` clears selection and closes panels of vanished tokens. A dropped player keeps their character; `/owner` with an empty name clears ownership; `/kick NAME` bans until host restart.
- Log: `PageUp`/`PageDown`/wheel over the bottom panel scroll, `End` to newest, default sticks to bottom. `F1` modal key help (`DrawHelpPanel`, text in `src/app/strings.h`), `Esc`/`F1` closes. `F3` journal (`DrawLogHistoryPanel`) reads `session.log` from disk (`core/log_history`, last 2000 lines / 512 KiB tail), shows past session headers, filters case-insensitively by author and text with `PlayerNameKey`, scrolls with `↑`/`↓`, `PgUp`/`PgDn`, wheel, `End`; it shrinks to the window height and measures the hint so nothing is clipped. `session.log` next to `.exe` (`src/core/session_log.h`) stores `[time] author: text`, survives runs, a new session starts with a header; `App::FlushSessionLog` writes only new lines via `ClientView::AppendedLogLines`. The in-game panel belongs to the party: host start, a fresh client join and a new party from the menu (`N` twice) clear it (`ClientView::ClearLog`), reconnect keeps it; past lines stay in `session.log` and `F3`.
- List mouse: an initiative row selects the token, a player row their first character, a scene row selects, double click opens the scene (editor too). Row geometry is shared with rendering: `InitiativeTokenAt`, `PlayerRowAt`, `SceneRowAt` in `src/render/ui_renderer`. The initiative panel exists only in combat: outside combat it is not drawn and clicks in its area are not captured.
- `Ctrl+=`/`Ctrl+-` UI scale 100/125/150/200%, `Ctrl+0` 100%: logical resolution via `SDL_SetRenderLogicalPresentation`, layout from `RenderSize()`, mouse via `SDL_ConvertEventToRenderCoordinates`. A scale above 100% applies only if the 640x660 menu panel with its fields fits the logical screen, otherwise it stays 100% (else the menu header and footer leave the window).
- `Alt`+RMB or `/ping` drops a "here" marker: `PingAt` → `PingMarker` event for all, 4 s (`kPingSeconds`); kept in `ClientView::Pings`, pruned by `PrunePings`, never saved.
- Map backdrop: `MapBackground{image, opacity, scale}` in `GameSnapshot`; only the file name travels over the network and the file lives next to each `.exe`; a missing file leaves the grid plus a label. It is author data: the editor sets it with `M` (a line taking a file name, `off`, `opacity N`, `scale N`, parsed by `ParseChatCommand`, applied by `core/map_background` `ApplyMapCommand`); in game `/map` is refused, `SetMapBackground`/`MapBackgroundUpdated` stay for protocol compatibility. Render order `ClearBoard` → `DrawMapBackground` → `DrawGrid`, image clipped to the map.
- Token portraits: `Token::portrait` is a file name next to `.exe` (validated by `IsSafeImageName`, `src/core/image_name.h`); `/portrait FILE` by owner or DM, `/portrait off` clears. Tokens are circles from a `SDL_RenderGeometry` fan (`DrawCircle`/`DrawTexturedCircle`, `src/render/grid_renderer.cpp`); no portrait → token colour plus name.
- Dice: `/roll d20+5`, `2d6+3`, `adv d20+5`, `dis d20-1`; `A` attack (Shift+A advantage, Ctrl+A disadvantage) against the token under the cursor: the server rolls d20 + attack bonus − exhaustion vs AC; natural 20 is a critical hit with doubled damage dice, natural 1 always misses; a hit applies the sheet damage (`core/attack`, `AttackToken`). `S` save, `I` initiative. Advantage and disadvantage from conditions, Dodging and the command stack cancel each other (2024). `core/conditions` gives the modifiers: blinded/poisoned/frightened/prone/restrained attacker; invisible or prone target (prone: advantage within 5 ft, disadvantage farther); restrained/paralyzed/stunned/petrified/unconscious target. A hit on a paralyzed or unconscious target within 5 ft is automatically critical (`IsAutoCriticalOnHit`). Frightened ignores the fear source — a documented simplification. Melee (`Token::attack_range == 0`) reaches 1 cell, diagonals included, and farther targets are rejected by the client and the server (`AttackReachCells`/`IsAttackInReach` in `core/attack`); the Reach property is not modelled yet. A ranged attack (`Token::attack_range > 0`, normal range in cells) has disadvantage within 5 ft of any other token (hostility is not stored: simplification) and beyond its normal range; beyond twice the range it is rejected. Cover comes from cell properties: half +2, three quarters +5 to AC and Dexterity saves, full cover rejects a direct attack; the DM's area template still covers the cell. Heavy obscurement is handled by the vision model. Parser and rolls in `src/core/dice`.
- Damage types and defences (`src/core/damage`): the sheet damage string may end with a Russian or English type (`1d8+2 fire`), `ParseDamageProfile` splits it; `Token::resist/vulnerable/immune` are bitmasks (`DamageTypeBit`), petrified adds resistance to everything and poison immunity (`EffectiveDamageProfile`). `AdjustedDamage` applies immunity → resistance (halve, round down) → vulnerability (double). `/damage N [type]` and `/aoe 2d6 15 [type]` carry a type; attacks use the attacker's type. Temp HP do not stack: the sheet keeps the greater value (`GameState::UpdateTokenSheet`); a long rest clears them.
- `K` conditions, `M` movement reach, `Alt`+LMB ruler. Reach via `ReachableCells` (`src/core/grid_map`); meters, cell 1.5 m (`src/core/units.h`). `core/movement` owns prone/crawl, the shared movement budget (`StandUpCostCells`, `RemainingMovementCells` — same numbers for `M` and the server), jumping (`J`, straight line up to 10 ft over pits/water, fixed because Strength is not modelled) and falling dice. Standing from prone costs half speed; `Ctrl`+LMB crawls at double cost and keeps the condition.
- Cell properties (`src/core/grid_map`): `GridMap` keeps `std::vector<CellProps>` over `Terrain`, so old scenes read with zero properties and sane defaults. Fields: `flags` (road, climbable), `water` (dry/shallow/deep), `current_dir` 0–8, `current_strength` 0–3, `slippery_dc`, `hazard` (index into the map's `HazardProfile` palette), `cover_sides` (2 bits per side: none/half/three quarters/full), `light` and `obscurement` (vision bullet below). Terrain `kSwamp`/`kMud`/`kSnow`/`kBrush` is difficult terrain (cost 2, never stacks with water: the maximum applies); a road cancels difficult terrain to cost 1. `MovementCost(cell, MovementProfile)` is the single source for `ReachableCells`, `PathCostCells`, `M` and the server: shallow water 2, deep water 2 without and 1 with `Token::swim_speed` (swimming is still allowed without it), climbing 2 without and 1 with `climb_speed`, then the 5–10–5 diagonal rule. Legacy `kWater` is deep water, `kPit` stays impassable, `kLava` gets the 10d10 fire profile. `GridMap::Hazards()` is the per-map palette (`DefaultHazards`: lava 10d10 fire, acid 2d6, spikes 1d10, fire 2d6); the server fires a profile on entry, turn start and turn end and marks it in `Token::hazards_done` (sorted, cleared in `ResetTurnEconomy` and at combat end), so re-entering the same lava within a turn does not repeat the damage; an optional save halves it. A slippery cell drops "prone" on a failed Dexterity save when the move spends more than half speed. `TryCurrent` on entry and at turn start: a Strength check (shared `save_bonus`) against `CurrentDc(strength)`; failure shifts the token up to `CurrentShiftCells` along the current, collisions and map borders stop it, no movement is charged. Underwater: ranged attacks have disadvantage within normal range and automatically miss beyond it; fire damage against a submerged target is halved (resistance). `CoverBetween`/`CoverBonus`/`SideTowards` sample the line of sight between attacker and target; a wall in between is full cover. `DrawCellProps` (`src/render/grid_renderer.cpp`) paints roads, water depth, current arrows, difficult-terrain hatching, cover marks on cell sides and hazard icons above `DrawTerrain` and below the tokens.
- Damage/heal: `DamageToken`/`HealToken` (`/damage N [type]`, `/heal N` on the selected token): temp HP first, 0 HP → unconscious (`kUnconscious`), healing clears it; damage whose remainder is at least `max_hp` kills instantly (SRD Instant Death). An attack hit reuses the same damage path (`GameServer::DamageAndLog`), so temp HP, damage types and concentration checks work the same. Rest is DM-only (`/rest [N]`, `/longrest`); both advance the scene clock (`GameSnapshot::game_time_seconds`) and log. The 2024 short rest (1 hour) spends up to `N` hit dice per character (`N` omitted — until full HP) on HP, each die heals `HitDieHeal(d{h}, con_modifier)` at least 1; the pool is `HitDiceMaximum(level)` (`core/levels`). A long rest (8 hours) restores HP and all hit dice, clears temp HP and removes exactly one exhaustion level; it does not clear other conditions. A long rest is refused until 16 hours (`kLongRestCooldownSeconds`) after the previous one started; rests are refused in combat (initiative interrupts) and when every character is at 0 HP. A character at 0 HP gains nothing (`RestParty`). Damage interruption inside an atomic rest command is not modelled: a rest resolves at once, so only the combat check represents it. The token card shows hit points and dice; `core_tests` covers the accounting (`TestDamageHealRest`, `TestShortRestHitDice`, `TestRestChoicesAndClock`).
- Falling: `/fall N` (DM) rolls `1d6` bludgeoning per 10 ft, at most `20d6` (`core/movement`, `FallDamageDice`); damage goes through `DamageAndLog` (resist/immunity, concentration, death) and any damage received adds "prone".
- Experience: `Token::xp`, level derived by `core/levels` (5e thresholds, `kMaxLevel` 20, `kMaxXp` cap). DM only: `/xp N` for the selected character, `/xp N all` for the party; level-ups go to the log; the token card shows XP and the next threshold (max at 20). Level is shown in the token panel and the `L` sheet; XP is not edited in the sheet. Level-up follows 2024: each level adds `HitPointsPerLevel` (average hit die d6 4 / d8 5 / d10 6 / d12 7 plus `con_modifier`, at least 1) to `max_hp` and to current `hp` unless it is 0; `ProficiencyBonus` (+2…+6 by tier) raises the stored `attack_bonus`/`save_bonus` by 1 at levels 5/9/13/17; levels 4/8/12/16 log the ability score improvement, 19 the epic boon. `hit_die` (sheet takes `d8` or `8`) and `con_modifier` are sheet fields; AC is not level-derived in 2024 and stays manual.
- Hit points from hit dice (`core/hit_points`): a new token has `Token::auto_hp` and its maximum is derived; old files read with `auto_hp = false` and keep the stored `max_hp`. Characters: `CharacterMaxHp` = `hit_die + con_modifier` at level 1, then `(level − 1) × HitPointsPerLevel`; monsters: `MonsterMaxHp` = `max(1, floor(count × (hit_die + 1) / 2) + count × con_modifier)` with `Token::hit_dice_count` (0 means "by level", i.e. characters). `RecomputeAutoHp` shifts current HP by the delta but never below 1 while conscious and never raises a token at 0 HP; it runs on spawn (`P`, `B`, DM), on sheet edits of die/Constitution/count or the auto flag, on `/xp`, and on scene load/`F9`/`Ctrl+Z` through the `GameState` constructor (invariant "auto = by dice"). `/maxhp` is refused in auto mode; manual mode keeps the old behaviour. The bestiary stores dice that reproduce its SRD stat-block HP; the `L` sheet has a max-HP / auto-HP / hit-dice row (`SheetField::kMaxHp/kAutoHp/kHitDiceCount`).
- `Condition{name, seconds, save_dc}` is game time: 6 seconds per turn in combat, ticking at the start of that token's turn; `/time N` (minutes, `s`/`m`/`h`) advances time outside combat; `0` means until removed. At the end of a token's turn a condition with `save_dc > 0` grants a save d20 + `save_bonus` − exhaustion against the DC: success removes it, failure keeps it. `K` panel: the full 2024 palette (`DefaultConditions`); `↑`/`↓` select in an 8-row scrolling window, `Space` toggles, `Shift+Space` sets until removed, `T` adds a custom condition (`kMaxConditionNameBytes`), `C` edits the DC, `−` removes one exhaustion level, `0` clears; the right side lists every condition on the token. `1`–`9` toggle the first nine. Exhaustion is a separate condition entry, levels 1–6: `ExhaustionPenalty` (−2×level on all d20), `ExhaustionSpeedPenaltyCells` (−1 cell×level), level 6 kills (`UpdateTokenCombat`), a long rest removes one. `IsSpeedZeroed` (grappled, restrained, paralyzed, stunned, petrified, unconscious, dead) zeroes speed; `EffectiveSpeedCells` is the shared budget for server and panel. Standing up from prone costs half speed (`HandleMove`); moving out of prone drops the condition. `StartEncounter` rolls initiative d20 + `initiative_bonus` − exhaustion; "surprised" gives disadvantage and is cleared after the roll. The default composition is characters plus living non-characters the table has noticed (`GameServer::DefaultParticipants`); the rest stay outside `Encounter::order` and join later (`JoinEncounterIfNeeded`: attack, damage, area, approach) with a d20 roll at the end of the round without shifting the current turn. `Shift+T` is the composition panel, `SetEncounterComposition` adds and removes a token; a new token in combat gets a real roll.
- Concentration on damage: d20 + `save_bonus` vs 10 or half damage, capped at 30 (`ConcentrationDc`); failure drops concentration (`kConcentration`) and logs. Death, 0 HP and any incapacitating condition (`IsIncapacitatingCondition`: unconscious, incapacitated, paralyzed, stunned, petrified, dead) drop it without a save. The sheet has a single save bonus for every save — a documented simplification until per-ability saves.
- Death saves: `/deathsave` at 0 HP rolls d20 (10+ success, 1–9 failure, natural 1 → two failures, 20 → 1 HP); exhaustion (−2 per level) lowers the result but not the natural value; 3 failures = dead (`kDead`), 3 successes stabilize but keep "unconscious" at 0 HP until healing. `death_save_successes`/`death_save_failures` in `Token`; a downed hit adds one failure (a critical hit two), healing resets them and clears "unconscious"; a stable character makes no further saves.
- Combat: a player is capped by speed per turn — the server computes `PathCostCells` with the optional 5–10–5 diagonal rule (`PathCost{cost, diagonal_parity}`) and deducts `Token::movement_used`. `M` shows the same range, the panel shows movement left; `movement_used`/`diagonal_parity` reset at own turn start and at combat start/end. At every turn change `App::FollowActiveTurn` selects the acting token: the DM gets any token, a player only their own character. The DM (`can_control_all`) moves monsters, NPCs and untaken characters freely, spends nothing, ignores paths; a character the DM took (`C`) follows player rules through `core/ownership` (`IsDmOwnedCharacter`/`FollowsPlayerRules`): turn, speed 0, occupied cell, path, movement budget, action and reaction, and `M`/the panel show its remaining movement. Outside combat players still need a valid path (walls, monsters, corners) but are not charged. `GameServer::TurnRejectReason` allows players to move and act only on their own `ActiveTokenId`; 0 HP and incapacitating conditions block movement, attacks and actions for everyone except master's tokens. `Token::action_used`/`bonus_action_used`/`reaction_used` and the Dash/Disengage/Dodge effects (`movement_bonus`, `disengaged`, `dodging`) reset at own turn start (`GameState::ResetTurnEconomy`). `A` spends the action; outside your turn it must pass `AttackToken::reaction` and only hits an adjacent target. `X` panel uses `UseTurnAction` for Dash (extra speed), Disengage, Dodge (disadvantage on attacks against it) and logs Help/Hide/Search/Study/Use Object; the token panel shows the three counters in combat.
- Movement blocking: monsters/NPCs block paths, player characters do not (you may pass through allies), and nobody may end a move on an occupied cell via the server; diagonal corners between two blocked cells are sealed. The DM may still stack tokens. A player may only target a cell their fog has explored (or the DM revealed); the client says the cell is unexplored and sends no command, the server rejects it as well.
- `F` area template: `1`–`3` circle/cone/line, `←`/`→` rotation, `↑`/`↓` radius/length, `,`/`.` line width, cursor origin; `Shift+F`/`Esc` remove the template, `F` only leaves the mode. The template (`AoeTemplate`) lives in `GameSnapshot`, DM-only, visible to all. `Enter` primes `/aoe `; `/aoe 2d6 15` (damage, DC) rolls damage once, each token under the template saves d20 + `save_bonus`, success halves. `AoeCells` for cells, damage via `GameState::DamageToken`, logged.
- Visibility and permissions live in `GameServer` (`ClientSnapshot(actor)`, `FogState(actor)`, `EventVisibleTo(event, actor)`, `can_control_all`), not in the renderer; players cannot add/remove tokens or control combat.
- Fog is per player: vision comes only from that player's own `TokenKind::kPlayer` tokens (owner == name, case-insensitive); NPCs/monsters grant no vision, the DM sees all. Until a player has a character they get the party fog from all player characters, even if the scene still holds their own fog record from a past party (`PlayerFog` ignores it without a character); with no visible cell at all the client draws a hint asking the DM to assign a character or open the map instead of a silent black map. Fog lives in the scene (`GameSnapshot::fog`, explored cells only, an empty owner = party fog), so `Ctrl+Z`, `F9` and scene switches restore it; a map of another size starts clean; `ClientSnapshot` strips all fog records. Unclaimed characters are locked; monsters and NPCs always belong to the DM (`kDmOwner`), so they cannot be released or handed to a player; the DM assigns/clears owners of characters.
- The DM reveals areas with `/reveal` (circle around the cursor), closes just that circle with `/unreveal`, clears every reveal with `/reveal off`; cells live in `GameSnapshot::revealed`, are saved with the scene and visible to every player, even without a character. After every world change the host sends each peer only its delta: `TokenAdded`/`TokenRemoved` for tokens entering or leaving that peer's fog, and `FogChanged` with just the changed cells (`GameServer::TakeViewDelta` keeps the last sent view, `MarkViewSent` resets it); the full `ViewUpdated` (snapshot + fog) goes out only on join and world swap. Events are filtered per peer.
- Vision follows SRD 5.2.1 (`src/core/light.h/.cpp`, `src/core/visibility.h/.cpp`): `CellProps.light` is 0 dark / 1 dim / 2 bright / `kAmbientLight` 3 = scene ambient; `CellProps.obscurement` is none/light/heavy; `GridMap::AmbientLight` defaults to bright so old scenes open as before; `ObscurementAt` makes trees lightly obscured. `ComputeLightField(map, sources)` paints scene and token lights along the line of sight (walls cut light, obscurement does not); `LightSource{cell, bright_cells, dim_cells}` comes from `TokenLightSources` (`src/core/scene_light.h`), which gathers every token's light, monsters included. `FogOfWar::Recompute(map, observers, light, max_sight_cells)` takes `Observer{cell, darkvision_cells, blinded}`: bright and dim cells are seen, darkness only within darkvision, heavy obscurement ends the ray but its own cell stays visible, and the observer's own cell is always visible unless blinded; `max_sight_cells <= 0` means no cap (the game), tests keep a small radius. Observers are the player's characters without blinded/unconscious/dead; `ClientSnapshot`/`TakeViewDelta`/`EventVisibleTo`/`MarkViewSent` hide tokens in heavy obscurement from players while the DM sees everything. `FogSnapshot`/`FogChanged` carry a light byte per cell, only for visible cells. `Token::darkvision_cells`/`light_bright_cells`/`light_dim_cells` are in cells (meters in the UI): the sheet field for darkvision and `/light BRIGHT [DIM]`/`/light off` (`SetTokenLight`, owner or DM; dim defaults to twice bright) set them. Editor: `9` cycles cell light (ambient → bright → dim → dark), `Shift+9` obscurement (none → light → heavy), `0` clears both, `F4` cycles the scene ambient, and the `G` inspector has light and obscurement fields; `DrawLight` (`LightView` in `grid_renderer.h`) paints dim/dark tints, smoke and light-obscurement hatching between cell props and fog, in game from the fog light field and in the editor from `ComputeLightField`.
- `F5` in game writes the party overlay explicitly (`OverlaySaver::Flush`); `F9` rereads `<campaign>.dndoverlay` from disk and rejects a fingerprint mismatch; host only. `savegame.bin` is gone.
- Campaign = scenes (`Campaign`/`Scene` in `src/core/campaign.h`) in `.dndcamp` files next to `.exe` (`src/core/campaign_io.h`, magic `DNDC`, library via `ListCampaignFiles`); the host tab selects the file with `↑`/`↓` or a click. It is an author file: the editor writes it, the game only reads it. Scene = full `GameSnapshot` + name + note.
- Party overlay (stage 8): `core/overlay` (`Overlay`/`OverlayScene`, `ApplyOverlay`, `ClearScene`, `DeletePartyScene`, `HasOverlayChanges`) and `core/overlay_io` (magic `DNDO`, atomic write, `FreshOverlay`, FNV-1a fingerprint, `OverlayPath`). `<campaign>.dndoverlay` holds played scene snapshots, added/deleted/renamed scenes and the active scene by `Scene::id`; `base_campaign_` + `overlay_` merge into the game's `campaign_`. A corrupt overlay or a fingerprint mismatch blocks host start with a menu status; `N` starts a new party (twice to confirm), `R` clears the active scene record back to the campaign, `A` accepts a party from another campaign version. The first host start in an empty slot writes the author campaign once; afterwards the game writes only the overlay. A failed overlay write is never dropped: `overlay_write_failed_` keeps the fresh party in memory, shows a save failure status and blocks campaign switch, editor entry and host start until a retry (`Flush`) succeeds. Editor `StartEditor` reloads the campaign and never sees the party; editor saves strip party traces (`fog`, `revealed`, `encounter`, `game_time_seconds`, `last_long_rest_seconds`) from the template.
- Scenes are DM-only and read-only in game: `Tab`/`/scene` list, `1`–`9` or `↑`/`↓`+`Enter` load a scene, `/scene NAME`; creating, renaming, noting and deleting maps happens only in the editor (`/scene new`, `/scene rename` are refused with a hint). A switch resets combat, clients get `ViewUpdated`. The overlay still reads added/deleted/renamed scene records of older parties (`ApplyOverlay`, `DeletePartyScene`), but the game writes none.
- `Scene::name`/`note` — the note shows under the name in the panel. Duplicate names rejected (`IsSceneNameAvailable`, `RenameScene`), `NextSceneName` picks a free one; `Scene::id` is a stable scene number (`NextSceneId`, `CopyScene`, `FindSceneIndex`), `Campaign::next_scene_id` never reuses numbers; `kCampaignVersion = 19`.
- Host autosave: a world-changing command (movement, combat, sheets) sets a flag; after 8 s (`kAutosaveDelay`) the active scene snapshot and the scene structure are written to `<campaign>.dndoverlay` by `OverlaySaver` (`core/overlay_save`) in a worker thread, so the frame never waits for the disk; chat and rolls don't set it. A new request replaces one that has not started, and a change during the write (`world_revision_`) schedules another pass. Explicit saves (F5, scene switch, host start, `ExitToMenu`, `Shutdown`) block on `Flush`. The editor alone uses `CampaignSaver` (`core/campaign_save`) for the `.dndcamp` file. The host menu shows campaign file, active scene, scene count and party state.
- Token/scene delete needs a second `Del` within 3 s (`kDeleteConfirmDelay`), the first press warns; panel status messages (delete warning, last-map refusal, editor hints) live 3 s (`core/status_message`), then the hint returns. `Ctrl+Z` host: undo the last DM action, ring buffer of 10 `GameSnapshot` (`undo_stack_`), snapshot taken before the world-changing command, combat restored too; scene switch/load/host start clear it; campaign structure (create/delete scenes) is not undoable.

## Serialization and protocol

- `src/core/serialization.cpp` — hand-written little-endian format for saves and TCP; strict decoders reject truncated data, extra bytes and out-of-range values.
- A serialized field change in `Token`, `GameSnapshot`, `Command`, `Event` → update encode/decode, extend `core_tests`/`net_tests`, bump `kSaveVersion` (`src/core/scene_io.h`) and `kProtocolVersion` (`src/net/protocol.h`); a mismatch rejects saves and clients. Saves and campaigns stay readable across releases: `SnapshotFormat` (`src/core/serialization.h`) and the version mapping in `scene_io`/`campaign_io` tell the decoder which fields a file has, from `kMinSaveVersion`/`kMinCampaignVersion` up to the current version.
- Login: `Challenge` carries a 16-byte nonce and the host's ephemeral X25519 key; `Hello` carries the player name, the client's key and HMAC-SHA256(password, transcript: nonce + both keys + name). The host verifies it, derives keys (X25519 shared secret + HKDF-SHA256) and answers with a sealed `SessionReady` carrying HMAC-SHA256(password, same transcript, server label); the client verifies it before accepting any data. From then on every frame is sealed: `[0xF2][u64 sequence][ciphertext][HMAC-SHA256 tag]` (ChaCha20, encrypt-then-MAC); a plaintext frame after the handshake closes the connection, a repeated or forged frame fails the sequence/MAC check. Only `Challenge`, `Hello` and a reject issued before the password check stay plaintext. The server checks the fingerprint and broadcasts `Roster` on join/leave/kick. Protocol version in the `Hello` header; on mismatch → `Reject` with both versions, then a plaintext `VersionMismatch` frame with the host version and the latest release from its manifest (old clients ignore the unknown type and keep the text reject), so the first five bytes (`DecodeHelloVersion`) layout is frozen. Login attempts share the message rate limit; brute force closes the connection.
- Noisy peers: `kMaxPeers` (8) connections (else a "no free slots" reject), `kMaxCommandsPerSecond` (30) commands/s per player (excess silently dropped), send queue `kMaxOutgoingBytes` (1 MiB) — overflow drops the connection, not the host; `TCP_NODELAY` on.
- Save: magic `DNDS`, version, payload length, snapshot. Campaign: magic `DNDC`, `kCampaignVersion` (`src/core/campaign_io.h`), payload length, scene count, active scene, scenes (name + nested snapshot); the campaign version is bumped separately from `kSaveVersion`. Both readers accept every version from `kMinSaveVersion`/`kMinCampaignVersion` up to the current one, so files of previous releases open; older files are rejected. `EncodeSnapshotAs`/`EncodeCampaignAs` write older layouts for the compatibility test `TestReadsPreviousVersions`.

## Style

- Google C++ via `.clang-format` (80 columns, 2-space indent), trailing return types `auto Fn() -> T`.
- `.clang-tidy` names: types/functions CamelCase, locals/variables `lower_case`, private members trailing `_`, constants `kCamelCase`.
- Project headers from `src/`, e.g. `#include "core/game_state.h"`.
- Player strings are Russian, in `src/app/strings.h`; use `core/utf8.h` for backspace/truncation, never byte-wise `pop_back`/`resize`.
- `dnd_core` must not depend on SDL; SDL only in `src/app` and `src/render`.
