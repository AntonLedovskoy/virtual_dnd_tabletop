# AGENTS.md

Virtual D&D tabletop, C++20 + SDL3. One `virtual_dnd_tabletop` binary:
authoritative host/DM or TCP client. No CI: build scripts and tests are the
source of truth; roadmap and weak spots in `PLAN.md`, user-facing overview in
`README.md` (keep it in sync with flags, keys and chat commands).

Language: code, comments, docs in Russian; identifiers and terms in English.
Local rules win where stricter than global (language, live UI checks).

Rules: always the latest D&D edition (2024, 5e revised). Where legacy 2014
rules differ, follow 2024 — level-up, AC, conditions, rests, movement.
Old rules appear only as a deliberate note in `PLAN.md`.

## Build and tests

- Windows: `.\build.bat` (debug default). `-p debug|release|relwithdebinfo|minsize`, `-c` reconfigure, `-j N` jobs, `-t`/`--tidy` runs `clang-tidy` on our `.cpp`, fails on any finding.
- `build.bat` runs `tools/build.sh` in MSYS2 UCRT64 (`C:\msys64` or `%MSYS2_ROOT%`); never run `tools/build.sh` from PowerShell.
- Binaries in `.build/<profile>/`, e.g. `.build/debug/virtual_dnd_tabletop.exe`.
- `virtual_dnd_tabletop.exe` — GUI-подсистема без окна консоли: `SDL_Log` дописывается в `virtual_dnd_tabletop.log` рядом с `.exe` (`src/app/file_log.h`), а `--help` и ошибка запуска показываются диалогом. Тесты остаются консольными.
- First configure fetches SDL3, SDL3_ttf, SDL3_image via FetchContent (network, minutes); `.build/<profile>` reused unless `-c`.
- Our targets: `-Wall -Wextra -Wpedantic`; deps use own flags; new warnings in our code = error.
- All tests: `ctest --test-dir .build/debug --output-on-failure`; one suite: `-R core_tests` or `.build/debug/dnd_core_tests.exe`.
- Tests: plain `main()` + `Expect`, no framework or per-test filter — add `TestX()` and call it from `main()` in `tests/core_tests.cpp`/`tests/net_tests.cpp`.
- `net_tests`: temp localhost port, 3 s timeouts, no external services.
- GUI needs a display: debug via `.vscode/launch.json`, not tests.
- UI: verify on live GUI with client-area screenshots, not `ctest`. Run host + client, walk the scenario, snapshot each changed visual behavior. SendInput/`SendKeys` in client coordinates is fine, outcome must be a snapshot.

## Релизы

- Релиз — аннотированный тег `vX.Y.Z` на чистом `master`; тело тега становится заметками в `latest.json`: `git tag -a vX.Y.Z -m "что нового"`, затем `git push origin master --tags`.
- `.\package.bat` собирает release (с `-c`, чтобы версия попала в бинарник) и кладёт в `dist/`: `virtual_dnd_tabletop.exe`, `virtual_dnd_tabletop-X.Y.Z-win64.zip`, `latest.json` и `notes.txt`. В zip — exe, `assets/fonts/DejaVuSans.ttf` и `LICENSE-DejaVu.txt`. Скрипт проверяет, что exe несёт версию тега, и хеширует его в манифест. `--allow-dev` — прогон пайплайна без тега, такой архив не выкладывать.
- Загрузка: `gh release create vX.Y.Z dist/virtual_dnd_tabletop.exe dist/virtual_dnd_tabletop-X.Y.Z-win64.zip dist/latest.json --title "virtual_dnd_tabletop X.Y.Z" --notes-file dist/notes.txt`; если `gh` нет — те же три файла через веб-форму Releases.
- Клиент читает манифест по стабильной ссылке `https://github.com/AntonLedovskoy/virtual_dnd_tabletop/releases/latest/download/latest.json`.
- Бамп `kProtocolVersion` — новый релиз в тот же день: клиент со старой версией получает отказ при подключении.
- Обновление ставится поверх той же папки: данные стола лежат рядом с `.exe`.

## Architecture

- `src/core` — logic without SDL: `GameState` (rules), `GameServer` (validates commands, ownership, fog, dice), `ClientView` (only state rendering reads), `LocalTransport` (in-process command/event queue), `ParseChatCommand` (`src/core/chat_command`, синтаксис `/roll`, `/map`, `/scene`, ... без роли и выбранного токена); login crypto in `src/core/sha256` (SHA-256/HMAC), `src/core/password`, session crypto in `src/core/x25519` (RFC 7748), `src/core/chacha20` (RFC 8439), `src/core/session_crypto` (HKDF, отпечатки, шифрование кадров), random bytes in `src/core/random` (системный `rand_s`, не `std::random_device`: на MinGW он предсказуем); case-insensitive player names in `src/core/player_name`.
- `src/net` — TCP framing, sockets, client/server; `NetServer` not authoritative, `App` owns `GameServer`, forwards peer commands. `src/app` — SDL window/input, Host/Join menu, host/client loop; `src/render` — drawing only; entry `src/main.cpp` on SDL3 callbacks (`SDL_MAIN_USE_CALLBACKS`).
- Логика стола без SDL лежит в `src/core` и покрыта `core_tests`: `camera` (клетка под курсором, центрирование, зум), `menu_model` (вкладки, порядок полей, лимиты, `host:port`), `ui_hint` (какие клавиши показывает нижняя подсказка), `navigation` (списки сцен и файлов), `autosave` (отложенная запись), `campaign_save` (запись кампании в отдельном потоке), `log_scroll`, `delete_confirm`, `chat_input` и UTF-8-правка в `utf8`. `App` только переводит SDL-события в эти функции и команды.
- Text only via `render/text_renderer` (`TTF_Text` + `TTF_DrawRendererText`, pooled objects, `BeginFrame()` per frame); per-frame `TTF_RenderText_Blended` textures forbidden.
- Startup: Host/Join/Map menu; `--host`, `--port`, `--connect HOST[:PORT]` start a mode, `--editor` map editor, `--menu` menu. Clients take `--name`, both sides `--password`. Host is always DM, plays locally, port 7777; names non-empty, unique and compared without case (`PlayerNameKey`, `DM` reserved in any case), `/kick NAME` removes a player and bans the folded name.
- Editor saves `scene.dndscene` next to `.exe` (snapshot format). Keys: `1`–`5` brushes, `[`/`]` width, `-`/`=` height, `Tab` scenes, `F2` panel, `F5` save scene, `F9` load `scene.dndscene`, `Enter` host, `Esc` menu; scene panel `↑`/`↓`/`1`–`9` select, `Enter` open, `N` new scene from map. Pan middle-drag, zoom wheel, editor and game.
- `L` token sheet (AC, speed, attack/save bonuses, damage, notes), `B` DM bestiary (`src/core/bestiary`, templates copied into token on spawn; 9 templates, `Shift`+digit spawns a group of 3–5 in free cells, `MonsterGroupCells`). Claim = one character per player, once per campaign; a player cannot release it (`R` and `/owner` are DM-only), afterwards owners are assigned only by the DM via `/owner`. The sheet of any character opens read-only to everyone, the DM edits it; token rename (`/rename`) and colour (`V`) are DM-only. The bottom hint is contextual (`core/ui_hint`: base keys, selected token, open mode, combat, role).
- Connection loss never resets the table: banner "Connection lost, reconnecting…", `NetClient::Reconnect` every 2 s (`kReconnectDelay`). New `Welcome` resends the world; `PruneStaleViewState` clears selection, closes panels of vanished tokens. Dropped player keeps their character; `/owner` with empty name clears ownership; `/kick NAME` bans until host restart.
- Log: `PageUp`/`PageDown`/wheel over bottom panel scroll, `End` to newest, default sticks to bottom. `F1` modal key help (`DrawHelpPanel`, text in `src/app/strings.h`), `Esc`/`F1` closes. `F3` journal (`DrawLogHistoryPanel`): reads `session.log` from disk (`core/log_history`, last 2000 lines / 512 KiB tail), shows past session headers, filters case-insensitively by author and text with `PlayerNameKey`, scrolls with `↑`/`↓`, `PgUp`/`PgDn`, wheel and `End`; the panel shrinks to the window height and measures the hint so nothing is clipped. `session.log` next to `.exe` (`src/core/session_log.h`) stores `[time] author: text`, survives runs, new session starts with header; `App::FlushSessionLog` writes only new lines via `ClientView::AppendedLogLines`.
- List mouse: initiative row selects token, player row their first character, scene row selects, double click opens scene (editor too). Row geometry shared with rendering: `InitiativeTokenAt`, `PlayerRowAt`, `SceneRowAt` in `src/render/ui_renderer`.
- `Ctrl+=`/`Ctrl+-` UI scale 100/125/150/200%, `Ctrl+0` 100%: logical resolution via `SDL_SetRenderLogicalPresentation`, layout from `RenderSize()`, mouse via `SDL_ConvertEventToRenderCoordinates`.
- `Alt`+RMB or `/ping` drops a "here" marker: `PingAt` → `PingMarker` event for all, 4 s (`kPingSeconds`); in `ClientView::Pings`, pruned by `PrunePings`, never saved.
- Map backdrop: `MapBackground{image, opacity, scale}` in `GameSnapshot`, only the file name travels over the network and the file lives next to each `.exe`; missing file leaves the grid plus a label. DM `/map FILE`, `/map off`, `/map opacity N`, `/map scale N` (`SetMapBackground` → `MapBackgroundUpdated`); render order `ClearBoard` → `DrawMapBackground` → `DrawGrid`, image clipped to the map.
- Token portraits: `Token::portrait` is a file name next to `.exe` (validated by `IsSafeImageName` in `src/core/image_name.h`); `/portrait FILE` by owner or DM, `/portrait off` clears. Tokens are circles built from a `SDL_RenderGeometry` fan (`DrawCircle`/`DrawTexturedCircle` in `src/render/grid_renderer.cpp`); no portrait → token colour plus name.
- Dice: `/roll d20+5`, `2d6+3`, `adv d20+5`, `dis d20-1`; `A` attack (Shift+A advantage, Ctrl+A disadvantage) against the token under the cursor: the server rolls d20 + attack bonus vs AC, natural 20 is a critical hit with doubled damage dice, natural 1 always misses, a hit applies the sheet damage (`core/attack`, `AttackToken`); `S` save, `I` initiative. Parser/rolls in `src/core/dice`.
- `K` conditions, `M` movement reach, `Alt`+LMB ruler. Temp HP, conditions in token; reach via `ReachableCells` (`src/core/grid_map`); meters, cell 1.5 m (`src/core/units.h`).
- Damage/heal: `DamageToken`/`HealToken` (`/damage N`, `/heal N` on selected token): temp HP first, 0 HP → "unconscious" (`kUnconscious`), healing clears it. An attack hit reuses the same damage path (`GameServer::DamageAndLog`), so temp HP and concentration checks work the same. Rest DM-only (`/rest`, `/longrest`), both advance game time and log: 2024 short rest (1 hour) spends `Token::hit_dice_spent` on HP — each die heals `HitDieHeal(d{h}, con_modifier)` at least 0 until HP is full or the pool is empty; the pool is `HitDiceMaximum(level)` (`core/levels`), restores only on a long rest (8 hours: full HP, all hit dice, clears temp HP and conditions). The token card shows `КХ: <осталось>/<всего>` and `core_tests` covers the dice accounting (`GameState::DamageToken`, `HealToken`, `RestParty`).
- Experience: `Token::xp`, level derived by `core/levels` (D&D 5e thresholds, `kMaxLevel` 20, `kMaxXp` cap). DM only: `/xp N` for the selected character, `/xp N all` for the whole party; level-ups go to the log, and the token card shows `XP: <опыт>/<порог следующего уровня>` (on the 20th level — `XP: <опыт>/макс.`). Level is shown in the token panel (`Ур.`) and the `L` sheet; XP is not edited in the sheet. Level-up follows 2024: each new level adds `HitPointsPerLevel` (average hit die d6 4 / d8 5 / d10 6 / d12 7 plus `con_modifier`, at least 1) to `max_hp` and to current `hp` unless it is 0; `ProficiencyBonus` (+2…+6 by tier) raises the stored `attack_bonus`/`save_bonus` by 1 at levels 5/9/13/17; levels 4/8/12/16 log the ability score improvement and 19 the epic boon. `hit_die`/`con_modifier` are sheet fields; AC is not level-derived in 2024 and stays manual.
- `Condition{name, seconds, save_dc}`: игровое время; в бою 6 секунд за ход, тик в начале хода своего токена; `/time N` (минуты, `s`/`m`/`h`) двигает время вне боя; `0` — до снятия. В конце хода токена состояние с `save_dc > 0` даёт спасбросок d20 + `save_bonus` против КС: успех снимает, провал оставляет. `K` panel: стандартные состояния на 1 минуту, `Shift+1–8` — до снятия, `↑`/`↓` — выбор, `C` — КС, показывает остаток; sheet gives initiative bonus, `StartEncounter` rolls d20 + bonus per token, logs.
- Concentration on damage: d20 + `save_bonus` vs 10 or half damage; failure drops "concentration" (`kConcentration`), logs.
- Death saves: `/deathsave` at 0 HP rolls d20 (10+ success, 1–9 failure, 20 → 1 HP); 3 failures = "dead" (`kDead`), 3 successes remove "unconscious", stabilize. `death_save_successes`/`death_save_failures` in `Token`; downed hit adds a failure, healing/rest reset.
- Combat: player capped by speed per turn — server computes `PathCostCells` with the optional 5–10–5 diagonal rule (`PathCost{cost, diagonal_parity}`), deducts `Token::movement_used`. `M` shows the same range, panel shows "Movement left"; `movement_used`/`diagonal_parity` reset at own turn start, combat start/end. DM (`can_control_all`) moves freely, spends nothing, ignores paths; outside combat players still take a valid path (walls, monsters, corners) but are not charged.
- Movement blocking: monsters/NPCs block paths, player characters do not (you may pass through allies), nobody may end a move on an occupied cell via the server; diagonal corners between two blocked cells are sealed. DM may still stack tokens. A player may only target a cell their fog has explored (or DM revealed); the client shows "Клетка не разведана" and sends no command, the server rejects it as well.
- `F` area template: `1`–`3` circle/cone/line, `←`/`→` rotation, `↑`/`↓` radius/length, `,`/`.` line width, cursor origin; `Shift+F`/`Esc` remove template, `F` only leaves mode. Template (`AoeTemplate`) in `GameSnapshot`, DM-only, visible to all. `Enter` primes `/aoe `; `/aoe 2d6 15` (damage, DC) rolls damage once, each token under template saves d20 + `save_bonus`, success halves. `AoeCells` for cells, damage via `GameState::DamageToken`, logged.
- Visibility/permissions in `GameServer` (`ClientSnapshot(actor)`, `FogState(actor)`, `EventVisibleTo(event, actor)`, `can_control_all`), not renderer; players cannot add/remove tokens or control combat.
- Fog is per player: vision comes only from that player's own `TokenKind::kPlayer` tokens (owner == name up to case); NPCs/monsters grant no vision, DM sees all. Until a player claims a character they get the party fog from all player characters. Fog itself lives in the scene (`GameSnapshot::fog`, explored cells only, a record with an empty owner is the party fog), so `Ctrl+Z`, `F9` and scene switches restore it; a map of another size starts clean; `ClientSnapshot` strips all fog records. Unclaimed characters are locked; free NPCs with empty owner are movable by players; DM assigns/clears owners.
- DM reveals areas with `/reveal` (circle around cursor), closes just that circle with `/unreveal`, and clears every reveal with `/reveal off`; cells live in `GameSnapshot::revealed`, are saved with the scene and visible to every player, even without a character. After every world change the host sends each peer only its delta: `TokenAdded`/`TokenRemoved` for tokens entering or leaving that peer's fog and `FogChanged` with just the changed cells (`GameServer::TakeViewDelta` keeps the last sent view, `MarkViewSent` resets it); the full `ViewUpdated` (snapshot + fog) goes out only on join and world swap. Events are filtered per peer.
- `F5` save, `F9` load `savegame.bin` next to `.exe` (`SDL_GetBasePath()`); host only.
- Campaign = scenes (`Campaign`/`Scene` in `src/core/campaign.h`) in `.dndcamp` files next to `.exe` (`src/core/campaign_io.h`, magic `DNDC`, library via `ListCampaignFiles`); the host tab selects the file with `↑`/`↓` or a click, host start and autosave use that file. Scene = full `GameSnapshot` + name + note; active scene mirrors host world (switch, `F5`/`F9`, host start, editor save).
- Scenes DM-only: `Tab`/`/scene` list, `1`–`9` or `↑`/`↓`+`Enter` switch, `R` rename, `E` note, `N` copy current, `Del` twice deletes; `/scene NAME`, `/scene new`, `/scene rename OLD NEW` (spaces ok, `ParseSceneRename`). Switch resets combat, clients get `ViewUpdated`.
- `Scene::name`/`note` — note under name in panel. Duplicate names rejected (`IsSceneNameAvailable`, `RenameScene`), `NextSceneName` picks free; `kCampaignVersion = 10`.
- Host autosave: world-changing command (movement, combat, sheets) sets flag, after 8 s (`kAutosaveDelay`) the active scene is written to the selected campaign file by `CampaignSaver` (`core/campaign_save`) in a worker thread, so the frame never waits for the disk; chat/rolls don't set it. A new request replaces one that has not started, and a change during the write (`world_revision_`) schedules another pass. Explicit saves (F5, scene switch, host start, `LoadSelectedCampaign`) block on `CampaignSaver::Flush`. Host menu shows campaign file, active scene and scene count.
- Token/scene delete needs second `Del` within 3 s (`kDeleteConfirmDelay`), first warns. `Ctrl+Z` host: undo last DM action, ring buffer of 10 `GameSnapshot` (`undo_stack_`), snapshot taken before the world-changing command, combat restored too; scene switch/load/host start clear it; campaign structure (create/delete scenes) not undoable.

## Serialization and protocol

- `src/core/serialization.cpp` — hand-written little-endian format for saves and TCP; strict decoders reject truncated data, extra bytes, out-of-range values.
- Serialized field change in `Token`, `GameSnapshot`, `Command`, `Event` → update encode/decode, extend `core_tests`/`net_tests`, bump `kSaveVersion` (`src/core/scene_io.h`) and `kProtocolVersion` (`src/net/protocol.h`); mismatch rejects saves and clients.
- Login: `Challenge` carries a 16-byte nonce and the host's ephemeral X25519 key; `Hello` carries the player name, the client's key and HMAC-SHA256(password, transcript: nonce + both keys + name). Host verifies it, derives keys (X25519 shared secret + HKDF-SHA256) and answers with `SessionReady` (sealed) carrying HMAC-SHA256(password, same transcript, server label); client verifies it before accepting any data. From then on every frame is sealed: `[0xF2][u64 sequence][ciphertext][HMAC-SHA256 tag]` (ChaCha20, encrypt-then-MAC); a plaintext frame after the handshake closes the connection, a repeated or forged frame fails the sequence/MAC check. Only `Challenge`, `Hello` and a reject issued before the password check stay plaintext. Server checks fingerprint, broadcasts `Roster` on join/leave/kick. Protocol version in `Hello` header; mismatch → `Reject` with both versions, so first five bytes (`DecodeHelloVersion`) layout is frozen. Login attempts share the message rate limit; brute force closes the connection.
- Noisy peers: `kMaxPeers` (8) connections (else "no free slots on the host"), `kMaxCommandsPerSecond` (30) commands/s per player (excess silently dropped), send queue `kMaxOutgoingBytes` (1 MiB) — overflow drops the connection, not the host; `TCP_NODELAY` on.
- Save: magic `DNDS`, version, payload length, snapshot. Campaign: magic `DNDC`, `kCampaignVersion` (`src/core/campaign_io.h`), payload length, scene count, active scene, scenes (name + nested snapshot); campaign version bumped separately from `kSaveVersion`.

## Style

- Google C++ via `.clang-format` (80 columns, 2-space indent), trailing return types `auto Fn() -> T`.
- `.clang-tidy` names: types/functions CamelCase, locals/variables `lower_case`, private members trailing `_`, constants `kCamelCase`.
- Project headers from `src/`, e.g. `#include "core/game_state.h"`.
- Player strings Russian, in `src/app/strings.h`; use `core/utf8.h` for backspace/truncation, not byte-wise `pop_back`/`resize`.
- `dnd_core` must not depend on SDL; SDL only in `src/app` and `src/render`.
