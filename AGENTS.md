# AGENTS.md

Virtual D&D tabletop, C++20 + SDL3. One `virtual_dnd_tabletop` binary:
authoritative host/DM or TCP client. No CI: build scripts and tests are the
source of truth; roadmap and weak spots in `PLAN.md`, user-facing overview in
`README.md` (keep it in sync with flags, keys and chat commands).

Language: code, comments, docs in Russian; identifiers and terms in English.
Local rules win where stricter than global (language, live UI checks).

Rules: always the latest D&D edition (2024, 5e revised). Where legacy 2014
rules differ, follow 2024 — level-up, AC, conditions, rests, movement.
Old rules appear only as a deliberate note in `PLAN.md`.
При разработке, проверке и обсуждении правил обязательно руководствуйтесь
шпаргалкой `docs/rules/cheatsheet-ru.md`; первоисточник —
`docs/rules/SRD_CC_v5.2.1.pdf` (SRD 5.2.1, CC-BY-4.0). В спорных местах прав
SRD, а не память и не сторонние сайты.

## Build and tests

- Windows: `.\build.bat` (debug default). `-p debug|release|relwithdebinfo|minsize`, `-c` reconfigure, `-j N` jobs, `-t`/`--tidy` runs `clang-tidy` on our `.cpp`, fails on any finding.
- `build.bat` runs `tools/build.sh` in MSYS2 UCRT64 (`C:\msys64` or `%MSYS2_ROOT%`); never run `tools/build.sh` from PowerShell.
- Binaries in `.build/<profile>/`, e.g. `.build/debug/virtual_dnd_tabletop.exe`.
- `virtual_dnd_tabletop.exe` — GUI-подсистема без окна консоли: `SDL_Log` дописывается в `virtual_dnd_tabletop.log` рядом с `.exe` (`src/app/file_log.h`), а `--help` и ошибка запуска показываются диалогом. Тесты остаются консольными.
- First configure fetches SDL3, SDL3_ttf, SDL3_image via FetchContent (network, minutes); `.build/<profile>` reused unless `-c`.
- Our targets: `-Wall -Wextra -Wpedantic`; deps use own flags; new warnings in our code = error.
- All tests: `ctest --test-dir .build/debug --output-on-failure`; one suite: `-R core_tests` or `.build/debug/dnd_core_tests.exe`.
- Tests: plain `main()` + `Expect`, no framework or per-test filter — add `TestX()` and call it from `main()` in `tests/core_tests.cpp`/`tests/net_tests.cpp`.
- `net_tests`: temp localhost port, 3 s timeouts, no external services.
- GUI needs a display: debug via `.vscode/launch.json`, not tests.
- UI: verify on live GUI with client-area screenshots, not `ctest`. Run host + client, walk the scenario, snapshot each changed visual behavior. SendInput/`SendKeys` in client coordinates is fine, outcome must be a snapshot.

## Релизы

- Релиз — аннотированный тег `vX.Y.Z` на чистом `master`; тело тега становится заметками в `latest.json`: `git tag -a vX.Y.Z -m "что нового"`, затем `git push origin master --tags`. `package.sh` дописывает в заметки постоянный хвост: обновляться поверх той же папки и проход SmartScreen при первой загрузке.
- `.\package.bat` собирает release (с `-c`, чтобы версия попала в бинарник) и кладёт в `dist/`: `virtual_dnd_tabletop.exe`, `virtual_dnd_tabletop-X.Y.Z-win64.zip`, `latest.json` и `notes.txt`. В zip — exe, `assets/fonts/DejaVuSans.ttf` и `LICENSE-DejaVu.txt`. Ассеты (`ASSET_PATHS` в `tools/package.sh`, сейчас шрифт и его лицензия) дополнительно копируются в `dist/upload/` с плоскими именами (`assets__fonts__DejaVuSans.ttf`) и попадают в `files` манифеста — это отдельные файлы релиза, без них автообновление шрифт не привезёт. Скрипт проверяет, что exe несёт версию тега и не импортирует внешних DLL (`objdump`: runtime MinGW и SDL статические, в архиве только exe и шрифт), и хеширует его в манифест. `--allow-dev` — прогон пайплайна без тега, такой архив не выкладывать.
- Загрузка: `gh release create vX.Y.Z dist/virtual_dnd_tabletop.exe dist/virtual_dnd_tabletop-X.Y.Z-win64.zip dist/latest.json dist/upload/* --title "virtual_dnd_tabletop X.Y.Z" --notes-file dist/notes.txt` (точный список печатает `package.sh`); если `gh` нет — те же файлы через веб-форму Releases, ассеты тоже.
- Обновление привозит ассеты: `latest.json` перечисляет их в `files` (`path`, `url`, `sha256`, `size`), `UpdateService` качает только отсутствующие или изменившиеся (сравнение sha256 с диском) в `<путь>.update` рядом с местом назначения, `InstallDownloadedUpdate` применяет их **до** подмены exe, а `ApplyStartupRecovery`/`RemoveStagedAssets` убирает недокачанные `*.update` под `assets/` при старте. Путь в манифесте — только `assets/…` (`IsSafeUpdatePath`): exe, кампании, журнал и портреты манифест не трогает. Новый ассет обязан быть безвреден для старого exe: если подмена сорвалась на файле, игрок остаётся на прежнем exe, а лишние файлы в `assets/` он не читает.
- Клиент читает манифест по стабильной ссылке `https://github.com/AntonLedovskoy/virtual_dnd_tabletop/releases/latest/download/latest.json`.
- Бамп `kProtocolVersion` — новый релиз в тот же день: клиент со старой версией получает отказ при подключении.
- Сохранения и кампании не ломаются о прошлый релиз: новое поле снимка добавляет ветку в `SnapshotFormat` и версию, старые версии остаются в диапазоне чтения.
- Обновление ставится поверх той же папки: данные стола лежат рядом с `.exe`.
- Проверка обновлений: `src/core/update` терпимо разбирает `latest.json` (обязательны `version`, `url`, `sha256`), `src/app/update_service` в фоновом потоке качает и проверяет exe через WinHTTP (redirect ALWAYS, 3 с/10 с, лимиты 64 КиБ/64 МиБ) и кладёт его в `virtual_dnd_tabletop.update.exe`. Сеть линкуется только в exe-цель (`winhttp`), `dnd_core` остаётся без SDL и сокетов.
- Баннер в меню «Доступна версия X» с кнопками «Обновить и перезапустить»/«Позже», версия и протокол на вкладке хоста. `DND_UPDATE_MANIFEST` — путь или URL манифеста для офлайн-проверки всего цикла; он же разрешает обновление developer build. `--no-update-check` выключает проверку.
- Несовпадение версий: хост шлёт текстовый `Reject` (его понимает любая версия) и сразу за ним кадр `VersionMismatch` (тип 10) — протокол и версия хоста плюс последняя версия из его манифеста. `AdviseUpdate` (`src/core/update`) решает, кто отстал; в меню модальный диалог версий с кнопкой обновления, только если обновиться должен клиент, иначе «Страница релизов». `Esc`/«Закрыть» возвращают меню, `Enter` запускает обновление.
- Подмена — только из меню: `CampaignSaver::Flush()`, `virtual_dnd_tabletop.exe` → `.old.exe`, `.update.exe` → `.exe`, `CreateProcess`, старый процесс выходит. Один экземпляр на папку держит именованный мьютекс (`src/app/instance_lock`), а `PlanStartupRecovery` до создания окна лечит обрыв между шагами. Developer build обновлений не предлагает.

## Architecture

- `src/core` — logic without SDL: `GameState` (rules), `GameServer` (validates commands, ownership, fog, dice), `ClientView` (only state rendering reads), `LocalTransport` (in-process command/event queue), `ParseChatCommand` (`src/core/chat_command`, синтаксис `/roll`, `/map`, `/scene`, ... без роли и выбранного токена), `core/damage` (типы урона, сопротивления и разбор «1d8+2 огонь»), `core/conditions` (палитра, истощение, модификаторы бросков); login crypto in `src/core/sha256` (SHA-256/HMAC), `src/core/password`, session crypto in `src/core/x25519` (RFC 7748), `src/core/chacha20` (RFC 8439), `src/core/session_crypto` (HKDF, отпечатки, шифрование кадров), random bytes in `src/core/random` (системный `rand_s`, не `std::random_device`: на MinGW он предсказуем); case-insensitive player names in `src/core/player_name`.
- `src/net` — TCP framing on Boost.Asio, client/server; `NetServer` not authoritative, `App` owns `GameServer`, forwards peer commands. Asio is header-only and comes from the system (`find_package(Boost CONFIG)`, MSYS2 `mingw-w64-ucrt-x86_64-boost`, Debian `libboost-dev`, macOS `brew install boost`); no WinSock calls remain, so `src/net` builds on Linux/macOS. Networking is asynchronous: `TcpConnection` and `TcpListener` each own an `io_context`, and `Poll()`/`Accept()` pump it; `QueueFrame` only enqueues frames, so a sender must be polled before its bytes leave. `Connected()` counts a connection in progress as alive. Keep `net_tests` polling both the host and the clients in every wait loop — otherwise a queued frame waits for the next poll. `src/app` — SDL window/input, Host/Join menu, host/client loop; `src/render` — drawing only; entry `src/main.cpp` on SDL3 callbacks (`SDL_MAIN_USE_CALLBACKS`).
- Логика стола без SDL лежит в `src/core` и покрыта `core_tests`: `camera` (клетка под курсором, центрирование, зум), `menu_model` (вкладки, порядок полей, лимиты, `host:port`), `ui_hint` (какие клавиши показывает нижняя подсказка), `navigation` (списки сцен и файлов), `autosave` (отложенная запись), `campaign_save` (запись кампании в отдельном потоке), `overlay_save` (запись партии), `log_scroll`, `delete_confirm`, `chat_input` и UTF-8-правка в `utf8`. `App` только переводит SDL-события в эти функции и команды.
- Text only via `render/text_renderer` (`TTF_Text` + `TTF_DrawRendererText`, pooled objects, `BeginFrame()` per frame); per-frame `TTF_RenderText_Blended` textures forbidden. В `App::LoadFont` после открытия DejaVu выставляется `TTF_SetFontLineSkip(height + 2)`: с обычным хинтингом hinted-глифы выше расчётной строки, и SDL_ttf обрезает хвосты «у»/«р» снизу (заметно в release).
- Startup: Host/Join/Map menu; `--host`, `--port`, `--connect HOST[:PORT]` start a mode, `--editor` map editor, `--menu` menu. Clients take `--name`, both sides `--password`. Host is always DM, plays locally, port 7777; names non-empty, unique and compared without case (`PlayerNameKey`, `DM` reserved in any case), `/kick NAME` removes a player and bans the folded name.
- Editor saves `scene.dndscene` next to `.exe` (snapshot format). Keys: `1`–`6` brushes, `7` road, `8` difficult terrain (cycles swamp → brush → snow → mud), `G` cell inspector, `P` character, `B` bestiary (same panel as the DM's), `M` map backdrop, `[`/`]` width, `-`/`=` height, `Tab` scenes/maps, `F2` panel, `F5` save scene, `F9` load `scene.dndscene`, `Enter` host, `Esc` menu; map panel `↑`/`↓`/`1`–`9` select, `Enter` open, `N` new map from the current one, `R` rename, `Del` twice delete (the last map stays). The inspector (`DrawEditorInspector`) edits the cell under the cursor: `Tab`/`↑`/`↓` field, `←`/`→` value, `Enter` applies, `Esc` closes; water, current direction and strength, hazard profile, road, climbing, slippery DC and the four cover sides. Left mouse on an empty cell paints while held (the stroke is interpolated with `core/editor_paint`), on a token it selects and drags it (`core/editor_token`), so the brush never paints over tokens; right mouse restores the floor (`CellProps` too) and with the road brush removes only the road; a token goes only on the second right click within 3 s (`DeleteConfirm`). `R` renames the selected token, `V` cycles its colour, `L` opens its editable sheet (the same panel as the DM's, saved into `scene_`); middle-drag pans, wheel zooms. Switching a map stores the current one in the campaign and saves it; every editor save strips party traces (`fog`, `revealed`, `encounter`, `game_time_seconds`, `last_long_rest_seconds`) so the template stays clean.
- `L` token sheet (AC, speed, swim/climb speeds, attack/save bonuses, damage, notes), `B` DM bestiary (`src/core/bestiary`, templates copied into token on spawn; 9 templates, `Shift`+digit spawns a group of 3–5 in free cells, `MonsterGroupCells`). Claim = one character per player, once per campaign; a player cannot release it (`R` and `/owner` are DM-only), afterwards owners are assigned only by the DM via `/owner`. The sheet of any character opens read-only to everyone, the DM edits it; token rename (`/rename`) and colour (`V`) are DM-only. The bottom hint is contextual (`core/ui_hint`: base keys, selected token, open mode, combat, role).
- Connection loss never resets the table: banner "Connection lost, reconnecting…", `NetClient::Reconnect` every 2 s (`kReconnectDelay`). New `Welcome` resends the world; `PruneStaleViewState` clears selection, closes panels of vanished tokens. Dropped player keeps their character; `/owner` with empty name clears ownership of a character; `/kick NAME` bans until host restart.
- Log: `PageUp`/`PageDown`/wheel over bottom panel scroll, `End` to newest, default sticks to bottom. `F1` modal key help (`DrawHelpPanel`, text in `src/app/strings.h`), `Esc`/`F1` closes. `F3` journal (`DrawLogHistoryPanel`): reads `session.log` from disk (`core/log_history`, last 2000 lines / 512 KiB tail), shows past session headers, filters case-insensitively by author and text with `PlayerNameKey`, scrolls with `↑`/`↓`, `PgUp`/`PgDn`, wheel and `End`; the panel shrinks to the window height and measures the hint so nothing is clipped. `session.log` next to `.exe` (`src/core/session_log.h`) stores `[time] author: text`, survives runs, new session starts with header; `App::FlushSessionLog` writes only new lines via `ClientView::AppendedLogLines`. The in-game panel belongs to the party: starting the host, a fresh client join and the menu's new party (`N` twice) clear it (`ClientView::ClearLog`), while reconnect keeps it; past lines stay in `session.log` and `F3`.
- List mouse: initiative row selects token, player row their first character, scene row selects, double click opens scene (editor too). Row geometry shared with rendering: `InitiativeTokenAt`, `PlayerRowAt`, `SceneRowAt` in `src/render/ui_renderer`. Панель инициативы видна только в бою: вне боя её не рисуют и клик по её месту не перехватывается.
- `Ctrl+=`/`Ctrl+-` UI scale 100/125/150/200%, `Ctrl+0` 100%: logical resolution via `SDL_SetRenderLogicalPresentation`, layout from `RenderSize()`, mouse via `SDL_ConvertEventToRenderCoordinates`. Масштаб выше 100% применяется, только если панель меню 640x660 с полями влезает в логический экран, иначе остаётся 100% (иначе шапка и низ меню уходят за окно).
- `Alt`+RMB or `/ping` drops a "here" marker: `PingAt` → `PingMarker` event for all, 4 s (`kPingSeconds`); in `ClientView::Pings`, pruned by `PrunePings`, never saved.
- Map backdrop: `MapBackground{image, opacity, scale}` in `GameSnapshot`, only the file name travels over the network and the file lives next to each `.exe`; missing file leaves the grid plus a label. It is author data: the editor sets it with `M` (a line taking a file name, `off`, `opacity N`, `scale N`, parsed by `ParseChatCommand` and applied by `core/map_background` `ApplyMapCommand`); in game `/map` is refused, `SetMapBackground`/`MapBackgroundUpdated` stay for protocol compatibility. Render order `ClearBoard` → `DrawMapBackground` → `DrawGrid`, image clipped to the map.
- Token portraits: `Token::portrait` is a file name next to `.exe` (validated by `IsSafeImageName` in `src/core/image_name.h`); `/portrait FILE` by owner or DM, `/portrait off` clears. Tokens are circles built from a `SDL_RenderGeometry` fan (`DrawCircle`/`DrawTexturedCircle` in `src/render/grid_renderer.cpp`); no portrait → token colour plus name.
- Dice: `/roll d20+5`, `2d6+3`, `adv d20+5`, `dis d20-1`; `A` attack (Shift+A advantage, Ctrl+A disadvantage) against the token under the cursor: the server rolls d20 + attack bonus − exhaustion vs AC, natural 20 is a critical hit with doubled damage dice, natural 1 always misses, a hit applies the sheet damage (`core/attack`, `AttackToken`); `S` save, `I` initiative. Advantage and disadvantage from conditions, dodging and the command stack and cancel each other (2024). `core/conditions` gives the modifiers: blinded/poisoned/frightened/prone/restrained attacker, invisible or prone target (prone: advantage within 5 ft, disadvantage farther), restrained/paralyzed/stunned/petrified/unconscious target; a hit on a paralyzed or unconscious target within 5 ft is automatically critical (`IsAutoCriticalOnHit`). Frightened ignores the fear source — a documented simplification. A ranged attack (`Token::attack_range > 0`, normal range in cells) has disadvantage in 5 ft of any other token (hostility is not stored: simplification) and beyond its normal range; beyond twice the range the attack is rejected. Cover comes from cell properties (below): half +2 and three quarters +5 to AC and Dexterity saves, full cover rejects a direct attack; the DM's area template still covers the cell. Heavy obscurement is handled by the vision model (below). Parser/rolls in `src/core/dice`.
- Damage types and defences (`src/core/damage`): the sheet damage string may end with a Russian or English type (`1d8+2 огонь`), `ParseDamageProfile` splits it; `Token::resist/vulnerable/immune` are bitmasks (`DamageTypeBit`), petrified adds resistance to everything and poison immunity (`EffectiveDamageProfile`). `AdjustedDamage` applies immunity → resistance (halve, round down) → vulnerability (double). `/damage N [ТИП]` and `/aoe 2d6 15 [ТИП]` carry a type; attacks use the attacker's type. Temp HP do not stack: the sheet keeps the greater value (`GameState::UpdateTokenSheet`), a long rest clears them.
- `K` conditions, `M` movement reach, `Alt`+LMB ruler. Temp HP, conditions in token; reach via `ReachableCells` (`src/core/grid_map`); meters, cell 1.5 m (`src/core/units.h`). `core/movement` owns prone/crawl, the shared movement budget (`StandUpCostCells`, `RemainingMovementCells` — the same numbers for `M` and the server), jumping (`J`, straight line up to 10 ft over pits/water, fixed because Strength is not modelled) and falling dice. Standing from prone costs half speed; `Ctrl`+LMB crawls at double cost and keeps the condition.
- Cell properties (`src/core/grid_map`): `GridMap` keeps `std::vector<CellProps>` over `Terrain`, so old scenes read with zero properties and sane defaults. `flags` (road, climbable), `water` (dry/shallow/deep), `current_dir` 0–8 and `current_strength` 0–3, `slippery_dc`, `hazard` (index into the map's `HazardProfile` palette), `cover_sides` (2 bits per side: none/half/three quarters/full), plus `light` and `obscurement` (vision bullet below). Terrain `kSwamp`/`kMud`/`kSnow`/`kBrush` are difficult terrain (cost 2, never stacks with water: the maximum applies); a road cancels difficult terrain for cost 1. `MovementCost(cell, MovementProfile)` is the single source for `ReachableCells`, `PathCostCells`, `M` and the server: shallow water 2, deep water 2 without and 1 with `Token::swim_speed` (swimming is still allowed without it), climbing 2 without and 1 with `climb_speed`, the 5–10–5 diagonal rule applies afterwards. Legacy `kWater` is deep water, `kPit` stays impassable, `kLava` gets the 10d10 fire profile. `GridMap::Hazards()` is the per-map palette (`DefaultHazards`: lava 10d10 fire, acid 2d6, spikes 1d10, fire 2d6); the server fires a profile on entry, turn start and turn end, marks it in `Token::hazards_done` (sorted, cleared in `ResetTurnEconomy` and at combat end) so re-entering the same lava within a turn does not repeat the damage, and an optional save halves it. A slippery cell drops "prone" on a failed Dexterity save when the move spends more than half speed. `TryCurrent` on entry and at turn start: a Strength check (shared `save_bonus`) against `CurrentDc(strength)`, failure shifts the token up to `CurrentShiftCells` along the current, collisions and map borders stop it, no movement is charged. Underwater: ranged attacks have disadvantage within normal range and automatically miss beyond it, and fire damage against a submerged target is halved (resistance). `CoverBetween`/`CoverBonus`/`SideTowards` sample the line of sight between attacker and target; a wall in between is full cover. `DrawCellProps` (`src/render/grid_renderer.cpp`) paints roads, water depth, current arrows, difficult-terrain hatching, cover marks on cell sides and hazard icons above `DrawTerrain` and below the tokens.
- Damage/heal: `DamageToken`/`HealToken` (`/damage N [ТИП]`, `/heal N` on selected token): temp HP first, 0 HP → "unconscious" (`kUnconscious`), healing clears it; damage whose remainder is at least `max_hp` kills instantly (SRD Instant Death). An attack hit reuses the same damage path (`GameServer::DamageAndLog`), so temp HP, damage types and concentration checks work the same. Rest DM-only (`/rest [N]`, `/longrest`), both advance the scene clock (`GameSnapshot::game_time_seconds`) and log: 2024 short rest (1 hour) spends up to `N` hit dice per character (`N` omitted — until full HP) on HP, each die heals `HitDieHeal(d{h}, con_modifier)` at least 1; the pool is `HitDiceMaximum(level)` (`core/levels`). Long rest (8 hours) restores HP and all hit dice, clears temp HP and removes exactly one exhaustion level; it does not clear other conditions. A long rest is refused until 16 hours (`kLongRestCooldownSeconds`) after the previous one started, and rests are refused in combat (initiative interrupts) and when every character is at 0 HP. A character at 0 HP gains nothing (`RestParty`). Damage interruption inside an atomic rest command is not modelled: rest resolves at once, so only the combat check represents it. The token card shows `КХ: <осталось>/<всего>` and `core_tests` covers the accounting (`TestDamageHealRest`, `TestShortRestHitDice`, `TestRestChoicesAndClock`).
- Falling: `/fall N` (DM) rolls `1d6` bludgeoning per 10 ft, at most `20d6` (`core/movement`, `FallDamageDice`); damage goes through `DamageAndLog` (resist/immunity, concentration, death) and any damage received adds "сбит с ног".
- Experience: `Token::xp`, level derived by `core/levels` (D&D 5e thresholds, `kMaxLevel` 20, `kMaxXp` cap). DM only: `/xp N` for the selected character, `/xp N all` for the whole party; level-ups go to the log, and the token card shows `XP: <опыт>/<порог следующего уровня>` (on the 20th level — `XP: <опыт>/макс.`). Level is shown in the token panel (`Ур.`) and the `L` sheet; XP is not edited in the sheet. Level-up follows 2024: each new level adds `HitPointsPerLevel` (average hit die d6 4 / d8 5 / d10 6 / d12 7 plus `con_modifier`, at least 1) to `max_hp` and to current `hp` unless it is 0; `ProficiencyBonus` (+2…+6 by tier) raises the stored `attack_bonus`/`save_bonus` by 1 at levels 5/9/13/17; levels 4/8/12/16 log the ability score improvement and 19 the epic boon. `hit_die` (в листе пишется `d8` или `8`)/`con_modifier` are sheet fields; AC is not level-derived in 2024 and stays manual.
- Hit points from hit dice (`core/hit_points`): a new token has `Token::auto_hp` and its maximum is derived, while old files read with `auto_hp = false` and keep their stored `max_hp`. Characters: `CharacterMaxHp` = `hit_die + con_modifier` at level 1, then `(level − 1) × HitPointsPerLevel`; monsters: `MonsterMaxHp` = `max(1, floor(count × (hit_die + 1) / 2) + count × con_modifier)` with `Token::hit_dice_count` (0 means "by level", i.e. characters). `RecomputeAutoHp` shifts current HP by the delta but never below 1 while conscious and never raises a token at 0 HP; it runs on spawn (`P`, `B`, DM), sheet edits of die/Constitution/count or the auto flag, `/xp`, and scene load/`F9`/`Ctrl+Z` through the `GameState` constructor (invariant "auto = by dice"). `/maxhp` is refused in auto mode; manual mode keeps the old behaviour. The bestiary stores dice that reproduce its SRD stat-block HP; the `L` sheet has the `Макс. HP / Авто HP / Костей` row (`SheetField::kMaxHp/kAutoHp/kHitDiceCount`).
- `Condition{name, seconds, save_dc}`: игровое время; в бою 6 секунд за ход, тик в начале хода своего токена; `/time N` (минуты, `s`/`m`/`h`) двигает время вне боя; `0` — до снятия. В конце хода токена состояние с `save_dc > 0` даёт спасбросок d20 + `save_bonus` − истощение против КС: успех снимает, провал оставляет. `K` panel: полная палитра 2024 (`DefaultConditions`: ослеплён, очарован, оглох, испуган, захвачен, выведен из строя, невидим, парализован, окаменел, отравлен, сбит с ног, опутан, оглушён, без сознания, истощение, застигнут врасплох), `↑`/`↓` — выбор с прокруткой окна из 8 строк, `Пробел` — вкл/выкл, `Shift+Пробел` — до снятия, `T` — своё состояние (`kMaxConditionNameBytes`), `C` — КС, `−` — снять уровень истощения, `0` — очистить; справа список всех состояний токена. `1`–`9` включают первые девять. Истощение — отдельные записи состояния, уровень 1–6: `ExhaustionPenalty` (−2×уровень ко всем d20), `ExhaustionSpeedPenaltyCells` (−1 клетка×уровень), шестой уровень убивает (`UpdateTokenCombat`), длинный отдых снимает один. `IsSpeedZeroed` (захвачен, опутан, парализован, оглушён, окаменел, без сознания, мёртв) обнуляет скорость, `EffectiveSpeedCells` — общий запас для сервера и панели; встать из «сбит с ног» стоит половину скорости (`HandleMove`), движение из prone снимает состояние. `StartEncounter` бросает инициативу d20 + `initiative_bonus` − истощение, «застигнут врасплох» даёт помеху и снимается после броска. Состав боя по умолчанию — персонажи и замеченные столом живые не-персонажи (`GameServer::DefaultParticipants`); остальные вне `Encounter::order` и вступают позже (`JoinEncounterIfNeeded`: атака, урон, область, приближение) броском d20 в конец раунда без сдвига текущего хода. `Shift+T` — панель состава боя, `SetEncounterComposition` вводит и выводит токена; новый токен в бою получает настоящий бросок.
- Concentration on damage: d20 + `save_bonus` vs 10 or half damage, capped at 30 (`ConcentrationDc`); failure drops "concentration" (`kConcentration`), logs. Death, 0 HP and any incapacitating condition (`IsIncapacitatingCondition`: unconscious, incapacitated, paralyzed, stunned, petrified, dead) drop it without a save. The sheet has a single save bonus for every save — a documented simplification until per-ability saves.
- Death saves: `/deathsave` at 0 HP rolls d20 (10+ success, 1–9 failure, natural 1 → two failures, 20 → 1 HP); exhaustion (−2 per level) lowers the result but not the natural value; 3 failures = "dead" (`kDead`), 3 successes stabilize but keep "unconscious" at 0 HP until healing. `death_save_successes`/`death_save_failures` in `Token`; a downed hit adds one failure (a critical hit adds two), healing resets them and clears "unconscious"; a stable character makes no further saves.
- Combat: player capped by speed per turn — server computes `PathCostCells` with the optional 5–10–5 diagonal rule (`PathCost{cost, diagonal_parity}`), deducts `Token::movement_used`. `M` shows the same range, panel shows "Movement left"; `movement_used`/`diagonal_parity` reset at own turn start, combat start/end. At every turn change `App::FollowActiveTurn` selects the acting token: the DM gets any token, a player only their own character. DM (`can_control_all`) moves freely, spends nothing, ignores paths; outside combat players still take a valid path (walls, monsters, corners) but are not charged. `GameServer::TurnRejectReason` allows players to move and act only on their own `ActiveTokenId`; 0 HP and incapacitating conditions block movement, attacks and actions for everyone, DM is unrestricted. `Token::action_used`/`bonus_action_used`/`reaction_used` and the Dash/Disengage/Dodge effects (`movement_bonus`, `disengaged`, `dodging`) reset at own turn start (`GameState::ResetTurnEconomy`). `A` spends the action; outside your turn it must pass `AttackToken::reaction` and only hits an adjacent target. `X` panel uses `UseTurnAction` for Dash (extra speed of movement), Disengage, Dodge (disadvantage on attacks against it) and logs Help/Hide/Search/Study/Use Object; the token panel shows the three counters in combat.
- Movement blocking: monsters/NPCs block paths, player characters do not (you may pass through allies), nobody may end a move on an occupied cell via the server; diagonal corners between two blocked cells are sealed. DM may still stack tokens. A player may only target a cell their fog has explored (or DM revealed); the client shows "Клетка не разведана" and sends no command, the server rejects it as well.
- `F` area template: `1`–`3` circle/cone/line, `←`/`→` rotation, `↑`/`↓` radius/length, `,`/`.` line width, cursor origin; `Shift+F`/`Esc` remove template, `F` only leaves mode. Template (`AoeTemplate`) in `GameSnapshot`, DM-only, visible to all. `Enter` primes `/aoe `; `/aoe 2d6 15` (damage, DC) rolls damage once, each token under template saves d20 + `save_bonus`, success halves. `AoeCells` for cells, damage via `GameState::DamageToken`, logged.
- Visibility/permissions in `GameServer` (`ClientSnapshot(actor)`, `FogState(actor)`, `EventVisibleTo(event, actor)`, `can_control_all`), not renderer; players cannot add/remove tokens or control combat.
- Fog is per player: vision comes only from that player's own `TokenKind::kPlayer` tokens (owner == name up to case); NPCs/monsters grant no vision, DM sees all. Until a player has a character they get the party fog from all player characters, even if the scene still holds their own fog record from a past party (`PlayerFog` ignores it without a character); with no visible cell at all the client draws «Нет обзора: попросите DM назначить персонажа или открыть карту» instead of a silent black map. Fog itself lives in the scene (`GameSnapshot::fog`, explored cells only, a record with an empty owner is the party fog), so `Ctrl+Z`, `F9` and scene switches restore it; a map of another size starts clean; `ClientSnapshot` strips all fog records. Unclaimed characters are locked; monsters and NPCs always belong to the DM (`kDmOwner`), so they cannot be released or handed to a player; DM assigns/clears owners of characters.
- DM reveals areas with `/reveal` (circle around cursor), closes just that circle with `/unreveal`, and clears every reveal with `/reveal off`; cells live in `GameSnapshot::revealed`, are saved with the scene and visible to every player, even without a character. After every world change the host sends each peer only its delta: `TokenAdded`/`TokenRemoved` for tokens entering or leaving that peer's fog and `FogChanged` with just the changed cells (`GameServer::TakeViewDelta` keeps the last sent view, `MarkViewSent` resets it); the full `ViewUpdated` (snapshot + fog) goes out only on join and world swap. Events are filtered per peer.
- Vision follows SRD 5.2.1 (`src/core/light.h/.cpp`, `src/core/visibility.h/.cpp`): `CellProps.light` is 0 dark / 1 dim / 2 bright / `kAmbientLight` 3 = scene ambient, `CellProps.obscurement` is none/light/heavy, and `GridMap::AmbientLight` defaults to bright so old scenes open as before; `ObscurementAt` makes trees lightly obscured. `ComputeLightField(map, sources)` paints the scene and token lights along the line of sight (walls cut light, obscurement does not); `LightSource{cell, bright_cells, dim_cells}` comes from `TokenLightSources` (`src/core/scene_light.h`), which gathers every token's light, monsters included. `FogOfWar::Recompute(map, observers, light, max_sight_cells)` takes `Observer{cell, darkvision_cells, blinded}`: bright and dim cells are seen, darkness only within darkvision, heavy obscurement ends the ray but its own cell stays visible, and the observer's own cell is always visible unless blinded; `max_sight_cells <= 0` means no cap (the game), tests keep a small radius. Observers are the player's characters without blinded/unconscious/dead; `ClientSnapshot`/`TakeViewDelta`/`EventVisibleTo`/`MarkViewSent` hide tokens in heavy obscurement from players while the DM sees everything. `FogSnapshot`/`FogChanged` carry a light byte per cell, only for visible cells. `Token::darkvision_cells`/`light_bright_cells`/`light_dim_cells` are in cells (meters in the UI): the sheet field «Тёмное зрение, м» and `/light ЯРКО [ТУСКЛО]`/`/light off` (`SetTokenLight`, owner or DM; dim defaults to twice bright) set them. Editor: `9` cycles cell light (ambient → bright → dim → dark), `Shift+9` obscurement (none → light → heavy), `0` clears both, `F4` cycles the scene ambient, and the `G` inspector has light and obscurement fields; `DrawLight` (`LightView` in `grid_renderer.h`) paints dim/dark tints, smoke and light-obscurement hatching between cell props and fog, in game from the fog light field and in the editor from `ComputeLightField`.
- `F5` in game writes the party overlay explicitly (`OverlaySaver::Flush`), `F9` rereads `<campaign>.dndoverlay` from disk and rejects a fingerprint mismatch; host only. `savegame.bin` is gone.
- Campaign = scenes (`Campaign`/`Scene` in `src/core/campaign.h`) in `.dndcamp` files next to `.exe` (`src/core/campaign_io.h`, magic `DNDC`, library via `ListCampaignFiles`); the host tab selects the file with `↑`/`↓` or a click. It is an author file: the editor writes it, the game only reads it. Scene = full `GameSnapshot` + name + note.
- Party overlay (stage 8): `core/overlay` (`Overlay`/`OverlayScene`, `ApplyOverlay`, `ClearScene`, `DeletePartyScene`, `HasOverlayChanges`) and `core/overlay_io` (magic `DNDO`, atomic write, `FreshOverlay`, FNV-1a fingerprint, `OverlayPath`). `<campaign>.dndoverlay` holds played scene snapshots, added/deleted/renamed scenes and the active scene by `Scene::id`; `base_campaign_` + `overlay_` merge into the game's `campaign_`. A corrupt overlay or a fingerprint mismatch blocks host start with a menu status; `N` starts a new party (twice to confirm), `R` clears the active scene record back to the campaign, `A` accepts a party from another campaign version. The first host start in an empty slot writes the author campaign once, afterwards the game writes only the overlay. A failed overlay write is never dropped: `overlay_write_failed_` keeps the fresh party in memory, shows "Не удалось сохранить партию" and blocks campaign switch, editor entry and host start until a retry (`Flush`) succeeds. Editor `StartEditor` reloads the campaign and never sees the party; editor saves strip party traces (`fog`, `revealed`, `encounter`, `game_time_seconds`, `last_long_rest_seconds`) from the template.
- Scenes DM-only and read-only in game: `Tab`/`/scene` list, `1`–`9` or `↑`/`↓`+`Enter` load a scene, `/scene NAME`; creating, renaming, noting and deleting maps happens only in the editor (`/scene new`, `/scene rename` are refused with a hint). Switch resets combat, clients get `ViewUpdated`. The overlay still reads added/deleted/renamed scene records of older parties (`ApplyOverlay`, `DeletePartyScene`), but the game writes none.
- `Scene::name`/`note` — note under name in panel. Duplicate names rejected (`IsSceneNameAvailable`, `RenameScene`), `NextSceneName` picks free; `Scene::id` — стабильный номер сцены (`NextSceneId`, `CopyScene`, `FindSceneIndex`), `Campaign::next_scene_id` номера не переиспользует; `kCampaignVersion = 19`.
- Host autosave: world-changing command (movement, combat, sheets) sets flag, after 8 s (`kAutosaveDelay`) the active scene snapshot and scene structure are written to `<campaign>.dndoverlay` by `OverlaySaver` (`core/overlay_save`) in a worker thread, so the frame never waits for the disk; chat/rolls don't set it. A new request replaces one that has not started, and a change during the write (`world_revision_`) schedules another pass. Explicit saves (F5, scene switch, host start, `ExitToMenu`, `Shutdown`) block on `Flush`. The editor alone uses `CampaignSaver` (`core/campaign_save`) for the `.dndcamp` file. Host menu shows campaign file, active scene, scene count and party state.
- Token/scene delete needs second `Del` within 3 s (`kDeleteConfirmDelay`), first warns; panel status messages (delete warning, "last map" refusal, editor hints) live 3 s (`core/status_message`), then the hint returns. `Ctrl+Z` host: undo last DM action, ring buffer of 10 `GameSnapshot` (`undo_stack_`), snapshot taken before the world-changing command, combat restored too; scene switch/load/host start clear it; campaign structure (create/delete scenes) not undoable.

## Serialization and protocol

- `src/core/serialization.cpp` — hand-written little-endian format for saves and TCP; strict decoders reject truncated data, extra bytes, out-of-range values.
- Serialized field change in `Token`, `GameSnapshot`, `Command`, `Event` → update encode/decode, extend `core_tests`/`net_tests`, bump `kSaveVersion` (`src/core/scene_io.h`) and `kProtocolVersion` (`src/net/protocol.h`); mismatch rejects saves and clients. Saves and campaigns stay readable across releases: `SnapshotFormat` (`src/core/serialization.h`) and the version mapping in `scene_io`/`campaign_io` tell the decoder which fields a file has, from `kMinSaveVersion`/`kMinCampaignVersion` up to the current version.
- Login: `Challenge` carries a 16-byte nonce and the host's ephemeral X25519 key; `Hello` carries the player name, the client's key and HMAC-SHA256(password, transcript: nonce + both keys + name). Host verifies it, derives keys (X25519 shared secret + HKDF-SHA256) and answers with `SessionReady` (sealed) carrying HMAC-SHA256(password, same transcript, server label); client verifies it before accepting any data. From then on every frame is sealed: `[0xF2][u64 sequence][ciphertext][HMAC-SHA256 tag]` (ChaCha20, encrypt-then-MAC); a plaintext frame after the handshake closes the connection, a repeated or forged frame fails the sequence/MAC check. Only `Challenge`, `Hello` and a reject issued before the password check stay plaintext. Server checks fingerprint, broadcasts `Roster` on join/leave/kick. Protocol version in `Hello` header; mismatch → `Reject` with both versions followed by a plaintext `VersionMismatch` frame with the host version and the latest release from its manifest (old clients ignore the unknown type and keep the text reject), so first five bytes (`DecodeHelloVersion`) layout is frozen. Login attempts share the message rate limit; brute force closes the connection.
- Noisy peers: `kMaxPeers` (8) connections (else "no free slots on the host"), `kMaxCommandsPerSecond` (30) commands/s per player (excess silently dropped), send queue `kMaxOutgoingBytes` (1 MiB) — overflow drops the connection, not the host; `TCP_NODELAY` on.
- Save: magic `DNDS`, version, payload length, snapshot. Campaign: magic `DNDC`, `kCampaignVersion` (`src/core/campaign_io.h`), payload length, scene count, active scene, scenes (name + nested snapshot); campaign version bumped separately from `kSaveVersion`. Both readers accept every version from `kMinSaveVersion`/`kMinCampaignVersion` up to the current one, so files of previous releases open; older files are rejected. `EncodeSnapshotAs`/`EncodeCampaignAs` write older layouts for the compatibility test `TestReadsPreviousVersions`.

## Style

- Google C++ via `.clang-format` (80 columns, 2-space indent), trailing return types `auto Fn() -> T`.
- `.clang-tidy` names: types/functions CamelCase, locals/variables `lower_case`, private members trailing `_`, constants `kCamelCase`.
- Project headers from `src/`, e.g. `#include "core/game_state.h"`.
- Player strings Russian, in `src/app/strings.h`; use `core/utf8.h` for backspace/truncation, not byte-wise `pop_back`/`resize`.
- `dnd_core` must not depend on SDL; SDL only in `src/app` and `src/render`.
