# virtual_dnd_tabletop

Виртуальный стол для D&D по правилам 2024 (5e revised): C++20 + SDL3,
один бинарник — либо авторитетный хост/DM, либо TCP-клиент. Стол с сеткой,
туманом войны, токенами, кампанией из сцен, бросками, боем и журналом.

Подробности реализации и текущее состояние — в `AGENTS.md` и `PLAN.md`.
Сборка, тесты и скрипты — источник истины, README даёт только обзор.

## Требования

- Windows, MSYS2 с окружением UCRT64 (`C:\msys64` или `MSYS2_ROOT`).
  WinSock-зависимостей больше нет, поэтому Linux и macOS тоже поддерживаются
  (автообновление пока только Windows/WinHTTP).
- CMake 3.25+, git, компилятор C++20.
- Boost 1.74+ системным пакетом: нужен только заголовочный Asio. MSYS2
  `mingw-w64-ucrt-x86_64-boost`, Debian/Ubuntu `libboost-dev`, macOS
  `brew install boost`.
- Первая конфигурация скачивает SDL3, SDL3_ttf и SDL3_image через
  `FetchContent`: нужна сеть и несколько минут.

## Сборка

```bat
.\build.bat                 :: debug (по умолчанию)
.\build.bat -p release      :: debug | release | relwithdebinfo | minsize
.\build.bat -c -j 8         :: переконфигурировать, 8 потоков
.\build.bat -t              :: плюс clang-tidy по нашему коду
```

Бинарник: `.build/<profile>/virtual_dnd_tabletop.exe`.
Под Windows `tools/build.sh` запускается только из MSYS2 UCRT64, `build.bat`
делает это сам.

На Linux и macOS тот же скрипт запускается напрямую:

```bash
./tools/build.sh            # debug
./tools/build.sh -p release
./tools/build.sh -t         # clang-tidy
.build/debug/virtual_dnd_tabletop
```

## Тесты

```bat
ctest --test-dir .build/debug --output-on-failure
ctest --test-dir .build/debug -R core_tests --output-on-failure
```

`core_tests` — логика без SDL, `net_tests` — локальный TCP на временном порту.
GUI проверяется вживую, не через `ctest`.

## Запуск

```text
virtual_dnd_tabletop [--menu] [--host] [--editor] [--port N]
                     [--name NAME] [--password PASS]
                     [--connect HOST[:PORT]] [--version] [--no-update-check]
```

- `--host` — открыть стол, хост всегда DM и играет локально, порт по
  умолчанию 7777.
- `--connect HOST[:PORT]` — подключиться клиентом.
- `--editor` — редактор карт и сцен.
- `--menu` — стартовое меню Host/Join/Map.
- `--name`, `--password` — имя игрока и пароль стола (проверка
  challenge-response, дальше кадры шифруются).
- `--version` — версия, версии протокола, сохранений и кампаний.
- `--help` — справка. `--no-update-check` выключает проверку обновлений.

Окно консоли у сборки нет: `SDL_Log` пишется в `virtual_dnd_tabletop.log`
рядом с `.exe`, `--help` и ошибки запуска показываются диалогом.

### Обновления

При запуске игра в фоне проверяет манифест последнего релиза. Если версия
новее, в меню появляется баннер «Доступна версия X»: «Обновить и
перезапустить» скачивает exe, проверяет sha256, заменяет файл и запускает игру
заново; стол, кампании и журнал остаются в той же папке. Вместе с exe
обновляются файлы рядом с ним — сейчас шрифт и его лицензия в `assets/fonts/`:
манифест перечисляет их пути, размеры и sha256, качается только то, чего нет
или что изменилось, а применяется это до подмены exe, поэтому новая версия
никогда не запустится со старым шрифтом. Во время партии подмена не
выполняется — баннер напоминает, что обновление будет после выхода в меню.
Developer build (сборка не на чистом теге) обновления не предлагает.
Офлайн-проверка всего цикла: переменная `DND_UPDATE_MANIFEST` с путём к
локальному `latest.json`.

Новую версию распаковывайте поверх той же папки: кампании, журнал и портреты
лежат рядом с `.exe`, и в другой папке стол окажется пустым. Первая загрузка
не подписанного exe проходит через SmartScreen — «Подробнее» → «Выполнить»;
дальше обновления идут через WinHTTP и этой метки не получают.

Если версии игры не совпадают, хост отказывает в подключении, а клиент видит
диалог: своя версия и протокол, версия хоста и последняя из манифеста. Кнопка
обновления появляется, только когда обновиться должен клиент; если отстал
хост, диалог просит DM обновиться первым.

### Быстрый старт

1. Хост: `virtual_dnd_tabletop.exe --host --name DM --password secret`.
2. Клиент: `virtual_dnd_tabletop.exe --connect 192.168.1.10:7777 --name Alice --password secret`.
3. Игрок забирает персонажа (`C`) и ходит по клеткам; DM ведёт сцену,
   туман, монстров и бой. Если игроков меньше, чем персонажей, DM берёт
   свободного персонажа себе (`C`) и играет за него по правилам игрока.

## Управление

| Клавиши | Действие |
| --- | --- |
| ЛКМ | выбрать токен, средняя кнопка + перетаскивание — панорама, колесо — зум |
| `Enter` | чат и команды (`/roll d20+5`) |
| `C` | забрать персонажа (один на игрока, раз за кампанию); у DM — взять свободного персонажа себе и отпустить повторным `C` (занятого игроком отдаёт только `/owner`) |
| `L` | лист персонажа (урон с типом, дальность атаки, тёмное зрение, сопротивления и уязвимости, макс. HP и авто-режим по костям), `B` — бестиарий (DM), `P` — персонаж (DM) |
| `A` | атака цели под курсором (`Shift` — преимущество, `Ctrl` — помеха); в чужой ход — реакция по соседней цели |
| `S` | спасбросок, `I` — инициатива, `T` — бой, `G` — следующий ход, `Shift+T` — состав боя (DM) |
| `K` | состояния: `↑`/`↓` — выбор, `Пробел` — вкл/выкл, `Shift+Пробел` — до снятия, `T` — своё состояние, `C` — КС спасброска, `−` — снять уровень истощения, `0` — очистить |
| `X` | действия хода (рывок, отход, уклонение, помощь…), `M` — дальность движения, `Ctrl`+ЛКМ — ползти, `J` — прыжок под курсором, `Alt`+ЛКМ — линейка |
| `F` | шаблон области (`1`–`3` форма, стрелки, `Enter` — `/aoe`) |
| `V` | цвет токена (DM), `Del` дважды — удалить |
| `Tab` | сцены (DM): только загрузка карт — `1`–`9`, `↑`/`↓` и `Enter`; `F5`/`F9` — сохранить/загрузить партию, `Ctrl+Z` — отмена |
| `F1` | справка, `F3` — журнал стола, `PgUp`/`PgDn`/`End` — лог |
| `Esc` | снять режим; без активного режима — выход в меню с подтверждением |
| `Ctrl+=`/`Ctrl+-`/`Ctrl+0` | масштаб UI 100/125/150/200% (выше 100% — если меню помещается в окно) |
| В редакторе: `1`–`9`, `0`, `F4`, `G`, `P`, `B` | кисти: стена, пол, дерево, вода, пропасть, лава, дорога (`7`), трудная местность (`8` циклично: болото, заросли, снег, грязь), свет клетки (`9` циклично: как сцена → яркий → тусклый → тёмный), затемнение (`Shift+9`: нет → слабое → сильное), `0` — сброс света и затемнения клетки, `F4` — освещённость всей сцены; `G` — инспектор клетки под курсором (свет, затемнение, вода, течение и сила, урон, дорога, лазание, скользко, укрытие и сторона: `Tab`/`↑`/`↓` — поле, `←`/`→` — значение, `Enter` — применить, `Esc` — закрыть); персонаж под курсором, бестиарий монстров; ЛКМ рисует (не поверх токена), по токену — выбрать и перетащить, ПКМ стирает — с зажатой кнопкой тоже (кистью дороги снимает только дорогу), по токену ПКМ дважды — удалить; `R` — имя токена, `V` — цвет, `L` — лист, `M` — подложка карты (файл, `off`, `opacity 60`, `scale 150`); `Tab` — карты: `↑`/`↓`, `Enter`, `R` — переименовать, `Del` дважды — удалить |

Нижняя подсказка контекстная: показывает клавиши для роли, выбранного
токена и открытого режима.

## Правила

- Карта у игрока открывается туманом войны: пока у него нет персонажа, он
  видит обзор всей партии, после назначения — только своих персонажей. Если
  видимых клеток нет совсем, клиент пишет «Нет обзора: попросите DM назначить
  персонажа или открыть карту»: это туман, а не потеря карты. Обзор дают только
  персонажи — монстры и NPC его не дают, их владелец всегда DM.
- Зрение считается по свету и препятствиям, а не по фиксированному кругу:
  в ярком и тусклом свете видно до стены, тьма открывается только в радиусе
  тёмного зрения персонажа, а сильное затемнение (дым, густая листва) обрывает
  взгляд — сама клетка видна облаком, но за ней уже нет. Свой токен виден
  всегда, кроме «ослеплён». Свет дают освещённость сцены, кисти редактора и
  факелы токенов: `/light 6` — яркий на 6 м, тусклый вдвое дальше; монстр с
  факелом тоже освещает комнату, даже если его самого не видно. Дерево теперь
  слабое затемнение и обзор не режет; вода, пропасть и лава луч не держат.
  Токен в сильном затемнении игрокам не показывается, DM видит всё.
- В бою сервер ведёт очередь хода: двигаться и действовать может только
  токен, чей сейчас ход; вне своего хода доступна одна реакция — атака по
  соседней цели. За ход одно действие (`X`: рывок, отход, уклонение, помощь,
  скрыться, поиск, изучение, использовать предмет) и одно бонусное действие;
  недееспособный токен (0 HP, без сознания, парализован и т. п.) не действует.
  Персонажа, взятого DM-ом клавишей `C`, мастер ведёт, но сам персонаж играет
  по правилам игрока: очередь, скорость 0, занятая клетка, путь, бюджет
  движения, действие и реакция; монстры, NPC и ещё не взятые персонажи
  двигаются свободно.
  В бой входят персонажи и замеченные ими монстры: остальные стоят вне
  очереди, пока их не ударят, не заденут областью или не подведёт DM.
  Вступивший бросает инициативу и ходит в конце раунда; состав правит DM
  через `Shift+T`.
- Состояния 2024 (ослеплён, сбит с ног, невидим, опутан, парализован…)
  меняют броски атаки: преимущество и помеха от всех источников складываются
  и гасятся взаимно, попадание по парализованному и лежащему без сознания в
  5 футах — критическое. Захват, опутанность и недееспособность дают скорость
  0; встать из «сбит с ног» стоит половину скорости, ползание (`Ctrl`+ЛКМ) —
  вдвое дороже и не встаёт. Прыжок (`J`) — по прямой до 10 футов через
  пропасть или воду; падение даёт `1d6` дробящего урона за 10 футов (не больше
  `20d6`) и «сбит с ног», если урон прошёл. Истощение 1–6 даёт −2 ко всем d20 и
  −5 футов скорости за уровень, шестой уровень — смерть, длинный отдых снимает
  один.
- Местность карты поверх рельефа: болото, грязь, снег и заросли — трудная
  местность (вход стоит 2, но не складывается с водой: всё равно 2), дорога
  отменяет её и стоит 1. Мелкая вода и лазание стоят 2, глубокая вода —
  плавание: 2 без скорости плавания и 1 с ней; лестница — обычная цена.
  Диагональ по правилу 5–10–5 считается после свойств. Вода скользкая — при
  движении больше половины скорости проверка Ловкости или «сбит с ног».
  Течение на входе и в начале хода требует проверки Силы, иначе сдвигает по
  течению. Укрытие задаётся по стороне клетки: половина даёт +2 к КД и
  спасброскам Ловкости, три четверти — +5, полное не даёт атаковать цель
  напрямую (область по клетке всё ещё действует; стена — полное укрытие).
  Лава, кислота, шипы и огонь — готовые профили урона: сервер бросает их при
  входе, начале и конце хода, метит сработавший за ход профиль (повторный
  вход в ту же лаву за ход не бьёт), спасбросок с КС делит урон пополам.
  Под водой дальнобойные атаки в обычной дистанции — с помехой, за ней —
  автоматом мимо, а огонь по погружённому получает сопротивление.
- Максимум HP новых токенов считается по костям хитов: у персонажа на 1-м
  уровне — вся кость плюс Телосложение, за каждый следующий — среднее кости
  плюс Телосложение; у монстра — среднее вниз по числу костей плюс
  Телосложение за каждую. Правка кости, Телосложения или числа костей и
  получение уровня пересчитывают максимум, а текущие HP сдвигаются на ту же
  дельту (раненый остаётся хотя бы с 1 HP, лежачий на нуле не встаёт). В листе
  `L` авто-режим можно выключить и задать максимум вручную; `/maxhp` в
  авто-режиме отказывает. Старые сцены читаются с ручным максимумом и не
  пересчитываются.
- Короткий отдых тратит выбранное число костей хитов (`/rest N`, без N — до
  полного HP), длинный отдых — не чаще чем раз в 16 часов игрового времени;
  персонаж на 0 HP не отдыхает. В бою отдых прерывает инициатива.
- Урон бывает с типом (дробящий, колющий, огонь, яд…): сопротивление делит
  его вдвое, уязвимость удваивает, иммунитет обнуляет. Временные HP не
  складываются — остаётся большее.
- `docs/rules/SRD_CC_v5.2.1.pdf` — официальный System Reference Document 5.2.1
  для D&D 2024 (5.5e), лицензия CC-BY-4.0.
- `docs/rules/cheatsheet-ru.md` — русская шпаргалка по базовым проверкам, бою,
  укрытиям, видимости, местности, отдыху и состояниям.

## Файлы рядом с `.exe`

- `*.dndcamp` — авторская кампания (сцены): её правит редактор, игра только
  читает и выбирает в меню хоста.
- `<имя>.dndoverlay` — партия: сыгранные сцены, активная сцена, туман, HP и
  время (записи новых и удалённых карт остаются от партий прошлых версий).
  Пишется автосохранением после изменений мира и по `F5`; `F9` перечитывает
  её с диска.
- `scene.dndscene` — сцена из редактора (`F5`/`F9` в редакторе).
- `session.log` — журнал сессий, его читает `F3`.
- `virtual_dnd_tabletop.log` — диагностический лог SDL.
- портреты и фоны карт — файлы-картинки по имени, сеть передаёт только имя.

В меню хоста строка партии показывает, продолжается ли игра в выбранной
кампании. `N` дважды начинает новую партию, `R` возвращает активную сцену к
кампании, `A` принимает партию, начатую на другой версии файла кампании.
Обратного переноса изменений партии в кампанию пока нет: правки карт, нужные
навсегда, делайте в редакторе. Если партию не удалось записать, меню покажет
«Не удалось сохранить партию» и не даст сменить кампанию или открыть
редактор, пока повторная запись не пройдёт: свежая партия остаётся в памяти.

Кампания, партия и сеть используют один рукописный little-endian формат
(`src/core/serialization.cpp`): смена полей требует бампа `kSaveVersion`,
`kCampaignVersion` и `kProtocolVersion`. Партия (`*.dndoverlay`) хранит те же
снимки сцен, поэтому её появление не меняет версию сохранения. Кампании и
партии читаются начиная с файлов v0.1.0
(`kMinSaveVersion`/`kMinCampaignVersion`): по версии файла декодер знает, каких
полей в нём нет. Протокол строгий — хост и клиент должны быть одной версии.

## Устройство

- `src/core` — правила и логика без SDL: `GameState`, `GameServer`,
  `ClientView`, камера, сцены, броски, бой, туман, логин и крипто
  (SHA-256/HMAC, X25519, ChaCha20).
- `src/net` — TCP-кадры поверх Boost.Asio (только заголовки, без WinSock),
  асинхронный клиент и сервер (сервер не авторитетен, `App` владеет
  `GameServer`); собирается на Windows и Linux/macOS.
- `src/app` — окно, ввод, меню Host/Join, цикл хоста и клиента.
- `src/render` — только отрисовка SDL3, текст через `render/text_renderer`.
- `tests/` — консольные `core_tests` и `net_tests`.

## Релизы

`.\package.bat` собирает release с версией из `git describe` и кладёт в
`dist/` exe, zip, `latest.json` и `notes.txt`; шрифт и лицензия из
`assets/fonts/` дополнительно уходят отдельными файлами релиза, чтобы
автообновление могло их заменить. Релиз — аннотированный тег `vX.Y.Z` на
чистом `master`, клиент читает манифест по стабильной ссылке
`releases/latest/download/latest.json`.

Сборка портативная: SDL3 и runtime MinGW слинкованы статически, в zip лежат
только `virtual_dnd_tabletop.exe` и `assets/fonts/`, внешние DLL не нужны.
`package.bat` проверяет это через `objdump` и не соберёт архив с зависимостью
от `libstdc++-6.dll`, `libgcc_s_seh-1.dll` или `libwinpthread-1.dll`.
